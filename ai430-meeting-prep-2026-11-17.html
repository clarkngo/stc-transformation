AI 430 Meeting Prep: Agentic CI/CD, GitHub Agentic Workflows, Gemini Enterprise Agent Platform, and Job-Ready Tools

Four topics raised for AI 430: MLOps and AgentOps. For each one: what it is, what the AI 430 draft already does, what's missing, and a recommendation that fits the course rules.

📄 Prepared Nov 17, 2026 📅 Meeting date and attendees: to fill in 🧭 Against outline v0.2 and the draft lesson site
BSAI reminder: the standing rules for AI 410 / 420 / 430 / 440 are in the course design constraints: fixed official outcomes, every hands-on unit in GitHub Codespaces, free tiers first (paid keys optional only), and two-week HOS in Weeks 1–8. Two of today's topics run into rule 3:
  • GitHub Agentic Workflows needs a coding-agent credential for every run: a GitHub Copilot entitlement or a paid API key. Whether a free student Copilot plan is enough is untested, so it can be required only if that test passes.
  • Gemini Enterprise Agent Platform needs Google Cloud billing after a 90-day express-mode trial, so it can only be optional or an instructor demo.
Nothing else here conflicts with the rules. The official outcomes already name "agentic workflows" (O2), so topic 1 needs no change to the outcomes.

Walk out with

  • Agentic CI/CD: mostly already there. HOS 2 ships the agent through the same CI/CD/CT pipeline and evaluation gate as the model. What's missing is an agent working inside the pipeline. Decide whether to add that.
  • GitHub Agentic Workflows (gh-aw): a strong fit, still to test. Recommended as an optional HOS 2 extension and an Application Challenge, made a required step only if a free student Copilot plan can run it.
  • Gemini Enterprise Agent Platform: teach it, don't build on it. Use it as the enterprise reference architecture that the free tools map onto, with an optional deploy for students who have credits.
  • Job-ready tools: AI 430 already teaches what postings ask for most (evals, observability, CI/CD, RAG, guardrails). The gaps are running MCP servers in production, OpenTelemetry, Kubernetes, and one cloud deploy. Pick which to add.

1 · CI/CD agentic workflow

Outcome O2: "Apply CI/CD/CT principles to automate deployment of machine learning models and agentic workflows"
Mostly addressed

"Agentic CI/CD" can mean two different things, and AI 430 covers the first well:

MeaningIn AI 430 nowStatus
CI/CD for an agent: ship the agent's code and prompts through tests, an evaluation gate and an automatic deployHOS 2 (Weeks 3–4): students write three GitHub Actions workflows. ci.yml tests every push, deploy.yml gates the model and the agent before deploying to a free Hugging Face Space, and ct.yml retrains weekly on drift. The Evaluate stage merges a prompt edit that raises the agent's success rate but doubles its tool calls, and asks whether the gate notices.Covered
An agent inside CI/CD: a coding agent runs as a pipeline step and investigates failures, reviews changes or opens issuesNot taught. Students use Copilot Chat in Agent mode to write the workflows, but no agent runs in them.Gap

Recommendation

Keep HOS 2's design: the evaluation gate for a prompt change is the core AgentOps idea. Add the second meaning as a small, clearly bounded step, using GitHub Agentic Workflows (topic 2) as the example. It fits O2 ("agentic workflows") and gives HOS 4 (O5) a real case of an agent that can act on a repository.

2 · GitHub Agentic Workflows (gh-aw)

github.github.com/gh-aw · read Nov 17, 2026
Not yet addressed · good fit · feasibility untested

What it is

You write a workflow as a Markdown file: YAML frontmatter for the trigger, permissions and allowed outputs, and plain-language instructions in the body. gh aw compile turns it into a hardened GitHub Actions workflow (a .lock.yml committed next to the .md), and GitHub Actions runs a coding agent on that trigger.

  • Engines: Copilot is the default. Claude Code and OpenAI Codex are also supported, Gemini CLI is marked deprecated, and an agy engine is experimental (Antigravity's CLI is called agy).
  • Security model: the agent job is read-only by default. Writes such as creating an issue or a pull request go through safe outputs, which are applied by separate jobs with scoped permissions, and can be previewed with staged: true. The Agent Workflow Firewall limits network access to an allowlist, a separate threat detection job checks the output, and protected environments can require a human approval.
  • Examples in the docs: "CI Doctor" investigates a failing CI run and opens an issue with the likely root cause. Others triage issues, review pull requests, write daily status reports, improve tests and update docs.
  • Status: the docs link a "technical preview" deck and mark several parts experimental. No general-availability label.

Fit with AI 430

WhereHow it would be used
HOS 2 (O2)Add a CI Doctor-style workflow to the HOS 2 repo. When ci.yml or the deploy gate fails, the agent reads the logs and opens an issue with a diagnosis. Students judge the diagnosis against the real cause in the Evaluate stage.
HOS 4 (O5)Use gh-aw's security model as a case study: read-only by default, safe outputs, the network allowlist, threat detection. Then red-team it: can a malicious issue body make the agent do something it shouldn't (prompt injection, unintended actions)?
Application ChallengeA no-credential option: critique a given gh-aw workflow file. Which permissions does it grant, what could go wrong, and what should go through a human?
Rule check (free tiers first): every run needs an engine credential. That means a fine-grained token with the "Copilot Requests" permission, drawing on the token owner's Copilot entitlement, or a paid Anthropic, OpenAI or Gemini key. The docs don't say whether a free student Copilot plan qualifies, or how private repositories and Actions minutes are counted. Agents run on Actions runners, not in the Codespace, which is fine: HOS 2's workflows already work that way. Until this is tested, gh-aw can be optional only.

Recommendation

  • Run a feasibility test before the HOS 2 build: a verified student GitHub account, a Classroom repo, gh extension install github/gh-aw, then the CI Doctor sample on a failing build. Record whether the Copilot engine runs and what it costs in AI credits.
  • If it passes: add it as an extension step in HOS 2's Understand & Refine stage, plus the HOS 4 red-team case.
  • If it doesn't: keep the no-credential Application Challenge and an instructor demo.

3 · Gemini Enterprise Agent Platform

Google Cloud's agent platform, announced April 22, 2026 as the evolution of Vertex AI
Partly addressed through ADK · platform not used

What it is

Google's platform for building, deploying, governing and optimizing enterprise agents. It replaces Vertex AI, and the Gemini Enterprise app for employees is built on it. Google's documentation names these parts: Model Garden, RAG Engine, Agent Platform Sessions (state within a conversation), Memory Bank (memory across sessions), and a governance layer of Agent Identity, Agent Registry and Agent Gateway.

AI 430 already uses the same family of tools: Google ADK for agents and Gemini through a free AI Studio key, with the starter's .env set to GOOGLE_GENAI_USE_VERTEXAI=FALSE. So the platform is the paid, managed version of what students build by hand. That makes it a useful map, not a lab.

Platform partWhat students build instead, for freeUnit
Managed deployment of an agentGitHub Actions deploy to a Hugging Face Space, behind an evaluation gateHOS 2
RAG EngineChroma vs. Qdrant in Docker, measured with RagasHOS 3
Sessions and Memory BankLong-term memory and memory retrieval performanceHOS 3, Term Project
Agent Identity, Registry and GatewayGuardrails through ADK callbacks; agent-to-agent calls with a2a-sdk; OWASP Top 10 for LLM Applications and NIST AI RMF as the enterprise frameworkHOS 4
Rule check (free tiers first): express mode lets new Google Cloud users try the platform without billing for 90 days. It is limited to quotas and "basic generative AI services", and it is separate from the $300 new-customer credit. After 90 days it needs billing, so it can't be a required step. Whether express mode includes agent deployment is untested.

Recommendation

  • Teach it as the reference architecture. In the HOS 4 lecture and the Week 8 architecture review, students put each part of their own pipeline next to the matching platform part and name what the managed version would add, mainly identity and governance.
  • Optional extension for the Term Project: students with credits, or a school-paid Google Cloud education grant, deploy their ADK agent to the platform. This is never graded as required.
  • Instructor demo: one recorded deploy of the HOS 4 agent, so every student sees it without paying.
  • To check: whether CityU can get Google Cloud education credits for the course, and what express mode allows.

4 · Tools that help students get hired

What agentic AI job postings asked for in 2026, and where AI 430 stands

Two job-posting counts give usable numbers; neither is a neutral survey.

  • Agentic AI Jobs Index: 2,331 open agentic roles at 193 companies, Sep 28, 2026. It is published by a vendor and doesn't describe its sourcing.
  • Simplilearn: 98 US postings with "agent" in the title, Oct 6, 2026. It is a training seller, and its sample leans toward Bay Area start-ups and big tech.

Read the numbers as direction, not precision.

A third count, 390 AI engineer postings from July 2026 on a personal blog, also puts evaluation in 56% of postings. Two warnings recur across all the sources: junior roles are rare (110 of the Index's 2,331 are junior or intern), and only about 9% of agentic roles are remote. Students need proof they can operate a system, not only a certificate.

What AI 430 already gives students: the skills that most often separate an AgentOps candidate are evaluation and observability. Evaluation appears in more than half of the postings in both counts that report it. AI 430 teaches both with open-source tools (Langfuse, Evidently, Ragas, promptfoo) that don't tie students to one framework. Add CI/CD, RAG performance and guardrails, and the course covers most of the "operate it in production" list.

Recommendation: ranked by job value against effort

  1. Keep the current core and say it plainly in the course copy: evals, tracing, CI/CD gates, RAG benchmarking, red-teaming. These are what employers name.
  2. Operate an MCP server (HOS 4): reuse the MCP server students built in AI 420. Trace it, put a tool allowlist on it, and red-team it for injection through tool descriptions and results. The highest-demand gap, low cost, no new account.
  3. OpenTelemetry (HOS 3): export the agent's traces in OpenTelemetry format alongside Langfuse, so the skill carries over to whichever tracing tool an employer uses (Datadog, Arize, LangSmith). Small change.
  4. gh-aw (HOS 2, optional): see topic 2. It shows the agent-in-the-pipeline pattern employers are starting to adopt.
  5. Containers and Kubernetes (Term Project, optional): package the agent as a Docker image; a local Kubernetes cluster (kind or k3d) in a Codespace is worth a feasibility test, not a commitment.
  6. One cloud deploy (Term Project, optional): Gemini Enterprise Agent Platform for students with credits (topic 3).
  7. LangGraph: discuss, don't switch. ADK stays the framework, matching AI 420 and the free Gemini key. A Concept Debate or Application Challenge can compare ADK and LangGraph so students can talk about both in interviews.

Make the work show: the Term Project repository is the job artifact. Its README should show the CI badge, the evaluation report, trace screenshots and the red-team findings, so a recruiter sees a running, measured system.

Questions for the meeting

Decisions that change what gets built next
  1. Does "CI/CD agentic workflow" mean the agent being deployed (already in HOS 2), an agent working in the pipeline (gh-aw), or both?
  2. Can the course rely on GitHub's free student Copilot plan? If yes, gh-aw can become a required step once tested.
  3. Is there budget, or a Google Cloud education grant, for Gemini Enterprise Agent Platform credits? Without one it stays optional.
  4. Which job-market gaps go in: MCP operations, OpenTelemetry, Kubernetes, a cloud deploy? Each adds time to a two-week HOS.
  5. Who runs the gh-aw and express-mode feasibility tests, and by when?
