Executive Summary

What's worth the dean's attention in two minutes

The Academy's subject — operational technology (OT/ICS) security — is not an STC teaching area today. Its teaching model is the actual find, and it's directly reusable.

1
It's a repeatable lesson pattern, not a one-off course. Every lesson follows the same skeleton: anchoring analogy → worked examples → interactive simulator or matching activity → knowledge check → reflection, with parallel guidance for self-learners and for instructors teaching it live. That skeleton is subject-agnostic.
2
It's built the same way STC already builds things. The lessons are self-contained, single-file HTML pages with no login and no backend — the same authoring pattern this repo already uses for every planning doc and course page. One of the Academy's tools is literally a prompt builder that generates the AI instructions to produce these modules. That's a near-zero-cost adoption.
3
It validates work already in motion, it doesn't start new work. The lesson skeleton maps cleanly onto the assessment infrastructure playbook's competency → task → rubric → scoring pipeline, and the delivery format maps onto the Open edX self-paced module design already planned for CityU X (see the AI Institute meeting notes). This is a second, independent institution arriving at a similar design — useful external validation, not a new direction.
4
No case for an OT/ICS credential yet. Nothing in these notes is market evidence that STC students or employers want OT security specifically. Per the micro-credentialing evidence review's own discipline, don't let an interesting teaching format become a justification for a new credential without a demand signal.

The Teaching Model, As Run

From the Academy notes — how each lesson was actually taught

Delivery layers, per lesson:

  • Lesson overview, framing what the lesson covers and how long it takes
  • Core lecture as a page hosted on GitHub Pages (no LMS login required to read it)
  • A NotebookLM-generated podcast version of the same content, for audio/on-the-go learners
  • Interactive simulators with built-in scenarios, run live with the instructor narrating over them
  • A dual guide: one path for self-directed learners, a separate path for instructors planning to teach it
  • An "interactive book" format that stands alone as a complete lesson with no external scaffolding needed

Inside each lesson or sub-lesson, the same components recur:

  • An instructor-facing teaching note (what to emphasize, common misconceptions, physical props to bring)
  • An anchoring analogy — a concrete, real-world hook the technical content is grounded in
  • Worked examples using named, real-world scenarios
  • An interactive simulator the learner can manipulate ("builder" style — click, break something, observe)
  • A matching quiz
  • A knowledge check, auto-graded with per-item explanations
  • A reflection step, done on the GitHub Pages side and then pasted into the LMS for instructor grading
  • "Chatting with a document" — learners bring a primary source into Claude, Gemini, or ChatGPT and interrogate it conversationally instead of reading passively, as a distinct comprehension exercise alongside the interactive-book format
  • Live regulatory advisories as current-events curriculum — pulling directly from CISA's ICS advisories feed (e.g. a Siemens S7-series PLC advisory) so the course stays anchored to this week's real vulnerabilities instead of only historical case studies
The pattern in one line: open content teaches and lets learners self-serve; the LMS only enters the picture at the very end, for the graded reflection. That's the same boundary already established for Open edX in the CityUX funnel — open layer teaches, formal layer certifies.

Three Concrete Walkthroughs

What the pattern looks like when you actually open the pages

Lesson 01 — Relay Logic to Industrial Convergence

Two-part structure (foundations lecture, then applied practice) walking from 1960s relay logic to today's IT/OT convergence. The anchoring analogy: two family branches that emigrated in 1968, stopped speaking, developed separate languages, and had to learn to share a house again by 2010 — used to explain why today's IT/OT security friction exists. Includes a "match the technology to its network reality" activity, a clickable air-gap-erosion simulation that shows isolation eroding as pressures accumulate, and a five-question auto-graded knowledge check. Instructor teaching notes are inline (e.g., "bring a physical decommissioned relay" ), separate from the self-learner path (time estimates, worked examples, a further-reading list).

OT-SIM — nine browser-based security training benches

Nine standalone HTML simulators (plus a notation primer), no install, no account, no internet dependency, covering mechanical failure, misconfiguration, and adversarial tampering scenarios — sensor reliability, stale controller data, protection-layer bypass, log correlation, evidence preservation. Each bench has a fault-injection control, a classification exercise, an instructor guide, and discussion questions. Explicitly supports three uses: 90-second classroom demos, full workshop sessions, or standalone self-paced assessment.

Interactive book engagement — reading companion for Countdown to Zero Day

A structured companion to a Stuxnet investigative book: eight tabs (timeline builder, attack-chain visualization, close reading, evidence sorting) mapped explicitly to six learning outcomes, all stored client-side in the browser so nothing is transmitted externally. Ends in a capstone: design a detection plan using only 2009-era technology and defend the spending priorities. This is the "self-contained lesson" format from the notes — it needs no LMS, no server, and no companion materials to function as a complete unit.

Cybersecurity Controls — general-security module

An 8-slide, NSF-funded tutorial teaching physical/administrative/technical controls and the six functional categories (preventative, detective, corrective, deterrent, recovery, compensating), ending in two categorization challenges (28 controls, then 20 controls). Worth noting: this module is general IT/cybersecurity content, not OT-specific — direct evidence the Academy's own team is already reusing its lesson skeleton for a broader security topic, which is exactly the transferability argument this briefing is making for STC.

Why This Matters Beyond OT

STC doesn't teach OT/ICS security — the transferable part is the design pattern

The specific subject matter (relay logic, SCADA, industrial protocols) has no obvious home in STC's current program mix. What's portable is the lesson architecture itself, and it maps onto content STC already builds or is planning:

"Chat with the document"
This is the single most STC-native technique in the whole Academy — it's an AI-literacy exercise, not an OT exercise. It requires no simulator to build and no subject-matter adaptation: any STC course with a primary source (a case study, a regulation, a research paper) can pilot this next class session by asking students to interrogate the reading in Claude, Gemini, or ChatGPT before discussion. Zero build cost, immediate fit with STC's AI-forward identity.
AI & safety content
STC's existing AI-safety and public-safety work (first-responder AI rollout, the SPD pilot) is exactly the kind of high-stakes, scenario-heavy subject the OT-SIM "fault injection + classification + instructor guide" format was built for. A simulator where learners inject a bad AI recommendation into a first-responder workflow and have to classify the failure mode is a direct port of the bench pattern.
AI-assisted development credential
The lesson skeleton (anchoring analogy → worked example → builder-style simulator → knowledge check → reflection) is a ready-made module template for the AI-assisted development ("vibe coding") credential already being designed — it fills in exactly the gap between "content" and "assessment" that credential's spec leaves open.
Any self-paced Open edX unit
The dual self-learner / instructor guidance, the reflect-on-open-page-then-paste-into-LMS handoff, and the "interactive book" self-contained format all match the flipped-Bloom's-Taxonomy, self-paced module design already scoped for CityU X's Open edX instance.

The Real Prize: AI-Assisted Authoring at Scale

The most exportable artifact from the Academy isn't a lesson — it's how the lessons get made

The Academy's module prompt builder is a form: an instructor answers questions about module type, audience (course level, multilingual learners, "likely reading on a phone"), desired structure (timeline, glossary, quiz, comparison table), and technical requirements (accessibility, output format), and the tool assembles a complete AI prompt that generates a finished, self-contained HTML lesson — ready to drop into a sandbox Canvas page for a quick check before assigning it.

This is worth flagging to the dean specifically because STC is already doing the manual version of this — every planning doc, playbook, and course page in this repo is a self-contained, AI-authored HTML file. The Academy's contribution is turning that ad hoc process into a repeatable instructor-facing form. Building an equivalent internal tool for STC/CityU X faculty is low-cost (it's a form plus a prompt template, no new infrastructure) and directly multiplies the output of the small team currently building CityU X content by hand.

Why this is the highest-leverage recommendation in this briefing

Everything else here is "borrow a good lesson template." This is "borrow the thing that lets one instructor produce ten of those templates without STC's content team touching each one." Given the CityU X build is currently resourced by one part-time lead plus one student/staff content builder, an authoring accelerant matters more than any single piece of content.

Gaps, Risks & What Not to Overclaim

Guardrails for how this gets presented

Don't say

"STC should offer an OT/ICS security micro-credential."

Do say

"STC should adopt this lesson-authoring pattern for content we already plan to build."

Don't say

"This proves demand for CityU X's model."

Do say

"This is a second institution's independent design landing near ours — useful triangulation, not market evidence."

Still open: licensing terms for reusing the OT-SIM simulator shells or lesson content directly (rather than just the structural pattern) haven't surfaced in the notes yet — CISA's advisory pages block automated access, so a person needs to open them directly to confirm details. There's also an external evaluator in the picture (a Qualtrics instrument from Redwood Consulting), which suggests the Academy has formal outcome tracking — worth asking the organizers whether that evaluation data or methodology is shareable, since it would be directly useful for CityU X's own completion/impact metrics.
