BSAI Course Design Constraints

Three rules every decision about AI-track course content, tools, and hands-on skill units (HOS) has to pass. They aren't up for debate in individual meetings. If a proposal breaks one, the proposal changes, not the rule.

Set September 23, 2026 Owner: Clark Applies to AI 410 · 420 · 430 · 440

1

The official course description is the source of truth

It cannot be changed
Rule
Each course's AAC-approved description and outcomes (approved program) are fixed. Materials, repos, schedules, and tools are adapted to fit the description, never the other way around.
In practice
  • Quote descriptions and outcomes word for word on every course page.
  • If existing material doesn't cover something the description promises, that gap is new content to build.
  • Never propose rewording an outcome to match what already exists.
  • If two courses seem to overlap, the descriptions decide which one owns the topic. Example: A2A belongs to AI 430 because only AI 430's description names agent-to-agent communication.
2

Everything runs in GitHub Codespaces

No local installs, no GPU, no desktop apps
Rule
A student's environment is a GitHub Codespace, as in AI 410. Every HOS has to work there from a browser.
In practice
  • Services that need a server (databases, brokers, dashboards) run in Docker inside the Codespace.
  • Each course repo ships a .devcontainer/ so it opens ready to run.
  • Plan around Codespaces quirks: forwarded ports, multiple terminals, containers that reset.
  • Watch the hours: students with GitHub Education get 180 core-hours a month, which is 90 hours on a 2-core machine and 45 on a 4-core one. Prefer 2-core, set short idle timeouts, and teach students to stop their Codespace.
3

Free tier and free resources first

No credit card required for anything a student must do
Rule
Use free tiers that need no credit card, or open-source and self-hosted tools. Anything that needs a paid key or a billing account is optional only and gets flagged, with a free alternative offered.
In practice
  • Free doesn't mean unlimited. For call-heavy exercises (agent-on-agent evals, LLM judges, security scans), estimate model calls per student per run against the free tier's rate limits before building.
  • Use smaller or cheaper models for the high-volume parts: simulated users, judges, attack probes.
  • Examples of what fails this rule: an OpenRouter key with credit, Google Cloud Run or Vertex AI (billing account needed), GPU-only tools like Isaac Sim.
✅

Meeting checklist

Run any proposed tool, unit, or project through these four questions
  • 1
    Which outcome or description phrase does this serve? If none, why is it in the course?
  • 2
    Does it run in a Codespace, from a browser, without a GPU?
  • 3
    Can a student do it with no credit card? If not, what's the free alternative?
  • 4
    Will a full class fit inside the free tier's rate limits and the Codespaces hour allowance?
