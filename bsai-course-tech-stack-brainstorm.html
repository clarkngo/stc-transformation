AI 420 / 430 / 440 — Technology Stack Brainstorm

Clark owns building out three BSAI AI-track courses: AI 420 (Agentic AI), AI 430 (MLOps and AgentOps), and AI 440 (Digital Twins and Physical AI), all AAC-approved as part of the Bachelor of Science in Artificial Intelligence. This page proposes a stack for each course that runs entirely in GitHub Codespaces on free tiers, and says whether the existing agent-development repo can serve as each course's hands-on base or whether something new is needed.

1. Ground Rules

Three constraints every technology choice below has to pass
Full rules and meeting checklist: BSAI Course Design Constraints. Read at the start of every course-design meeting.
Description is fixed
Each course's AAC-approved description and outcomes (approved program) are the source of truth and don't change. When existing material doesn't cover something the description promises, the gap is new content to build. The outcome wording is never softened to fit the material.
Runs in Codespaces
Students work in GitHub Codespaces, as in AI 410. No local installs, no GPU, no desktop apps. Services that need a server run in Docker inside the Codespace.
Free tier first
Only free tiers with no credit card, or open-source tools. Anything that needs a paid key or a billing account is flagged below as optional, never required. Where a free tier's rate limits could be the bottleneck, that's flagged too.
Legend: Reuse already exists in agent-development or AI 410 · New needs to be built · Caution works, but with a limit worth planning around.

2. The agent-development Repo — Current State

After the Sep 23 update to google-adk 2.9.2 and current Gemini models
What's there
Twelve ADK walkthroughs (hos-google-adk/hos01–hos12): first agent, custom tools, provider switching, structured output, session state, persistent memory, supervisor, stateful multi-agent, callbacks, and sequential, parallel, and loop pipelines. Also an A2A example (hos-a2a/hos01) and a full-stack movie app. The Sep 23 commit moved hos-google-adk to google-adk==2.9.2 and gemini-3.6-flash.
Still to fix
  • hos01 still uses gemini-2.0-flash. It's the only ADK example the update missed, and the first one students run.
  • hos03 still calls Claude and GPT through OpenRouter, which needs a paid key. Keep the provider-switching lesson but make it free: switch between two Gemini models, or Gemini and a small local model.
  • hos-a2a and movie-app-ai-powered weren't updated and still use gemini-2.0-flash.
  • hos08–hos12 have no requirements.txt.
  • No .devcontainer/, so the repo can't open in a ready-to-run Codespace with one click.
Role per course
AI 420: the base. It covers most of the course, with four new units to add. AI 430: covers the agent side only; the MLOps side needs a new companion repo. AI 440: contributes only the decision-making agent; needs its own repo.

Verdict: needs its own repo; the hardest fit for Codespaces + free tier

The O4 compromise, and what it means for the feasibility study. CPU rendering in a Codespace meets the outcome, but only at small scale. The Digital Twins Lab Feasibility Study's Phase 1 open-source stack (Node-RED, InfluxDB, Grafana, Wokwi, optional Ditto) carries over, now running in Docker in the Codespace. Its Phase 2B NVIDIA track (Omniverse, Isaac Sim) needs an RTX GPU and can't run in Codespaces. It becomes an optional extension funded by paid GPU time or free academic credits, never a requirement. Phase 2A (Azure Digital Twins) is likewise optional, via Azure for Students credit.

6. Cross-Course Constraints

What applies to all three courses (and AI 410)
Codespaces hours
Students with GitHub Education get the Pro allowance: 180 core-hours a month. That's 90 hours on a 2-core machine but 45 on a 4-core one. AI 440's Docker stack and AI 430's MLflow + Qdrant setup will want 4 cores. Set short idle timeouts and teach students to stop the Codespace when they're done.
Gemini free-tier limits
The main risk is AI 420's automated agent testing and AI 430's security scanning, which make many model calls per run. Estimate calls per student per run before building either unit, and use smaller models for the simulated user, the judge, and the attack probes.
One devcontainer pattern
A shared .devcontainer/ setup across all four course repos, so "open in Codespaces" behaves the same in every course.
Sequencing
410 → 420 → 430 is a natural progression: build an agent, then operate agents in production. AI 440 is mostly independent but reuses an ADK agent from 420 for its decision-making layer, so taking 420 first helps.

7. Open Questions

Still to decide
Free-tier fit for evals & red-teaming
Do AI 420's agent-on-agent test suites and AI 430's security scans fit Gemini's free-tier rate limits at class scale? Needs a measured dry run.
Capstone samples & Google Cloud
Do the vendored marketing-agency and software-bug-assistant samples run on a plain Gemini API key, or do they expect Vertex AI or BigQuery? If the latter, they need a free-tier adaptation before they're offered as capstone starters.
Hands-on unit (HOS) mic access for voice
hos02's voice variant needs microphone access from a browser tab connected to a Codespace. Test it before making it required.
AI 440 GPU path
Whether to pursue free academic GPU credits (NVIDIA, Azure for Students) for an optional Isaac Sim extension. The feasibility study's ~$6,400 local-hardware request is moot for the core course under the Codespaces constraint.
