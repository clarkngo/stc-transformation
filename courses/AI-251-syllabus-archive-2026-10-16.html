Course Description

Bridges classical statistics and the high-dimensional mathematics of Machine Learning and Deep Learning using Python. Students evolve from data explorers into architects of mathematical optimization—mastering inferential statistics (t-tests, ANOVA, regression), Linear Algebra for tensors, Multivariable Calculus, and backpropagation to understand how gradients power model learning.

Course Outcomes

This course will prepare students to:

O1 Map classical statistical concepts (variance, correlation) to their Linear Algebra equivalents (norms, dot products).

O2 Execute complex data transformations and matrix operations on high-dimensional datasets using NumPy and Tensors.

O3 Interpret Gradient Descent paths and loss surfaces to diagnose why an AI model may fail to converge.

O4 Justify the selection of specific probability distributions (e.g., Gaussian, Bernoulli) when designing the loss function of a Deep Learning model.

O5 Build and visualize an end-to-end optimization loop in Python that uses derivatives to minimize prediction error.

Additional Information

Core Concepts & Tools

  • Python essentials (Week 1 ramp-up): variables, lists, loops, functions, and reading files

  • Python for data analysis in Jupyter notebooks inside GitHub Codespaces: pandas for tabular data, Matplotlib and seaborn for plots

  • Descriptive statistics and visualization: center, spread, shape, histograms, box plots, scatter plots

  • Sampling distributions and inference: confidence intervals, t-tests, chi-square, one-way ANOVA, and regression inference (SciPy, statsmodels)

  • Statistics as linear algebra: vectors, norms, dot products, matrices, and least-squares regression as a matrix problem

  • NumPy arrays and PyTorch tensors: shape, axes, broadcasting, reshaping, and batched matrix operations on high-dimensional data

  • Multivariable calculus for learning: partial derivatives, gradients, the chain rule, and computational graphs

  • Gradient descent: learning rate, feature scaling, loss surfaces, and diagnosing divergence, oscillation, and stalls

  • Probability distributions and loss functions: Gaussian → mean squared error, Bernoulli → binary cross-entropy, maximum likelihood

  • Backpropagation: hand-coded gradients checked against PyTorch autograd

Every tool in this course is free and open source. No API keys, billing accounts, or GPUs are required; PyTorch runs on CPU in a 2-core Codespace.

Hands-On Skill (HOS) - Grading Criteria

HOS is designed to support “learning-by-example” and “learning-by-doing.” The instructor will assign HOS exercises to a pair of students in class or individually online.   • HOS 1 — Exploring and Testing Data in Python

The HOS opens with a Week 1 Python ramp-up, because the course's only prerequisite is mathematics: students who have not programmed in Python work through a short notebook on variables, lists, loops, functions, and reading a CSV file before the analysis begins, and students who already know Python can skip ahead. Students then use an AI coding assistant in GitHub Codespaces to load a public dataset with pandas, describe it (center, spread, and shape), and plot histograms, box plots, and scatter plots. They simulate sampling distributions with NumPy to see where the normal curve and confidence intervals come from, then run the classic tests with SciPy and statsmodels: one- and two-sample t-tests, chi-square, and one-way ANOVA. Students check whether the AI-generated analysis picked the right test and met its assumptions, explain in their own words what a p-value does and does not say, and compute a two-sample t statistic by hand with NumPy alone to match the library's result.

  • HOS 2 — Statistics as Linear Algebra: Vectors, Matrices & Tensors

Students rewrite their HOS 1 statistics as vector operations: variance as the squared norm of a centered vector, covariance as a dot product, and correlation as the cosine of the angle between two centered vectors. They move from pandas to NumPy arrays and PyTorch tensors, working with shape, axes, broadcasting, and batched matrix multiplication on a high-dimensional dataset (for example, a set of images stored as one tensor). They fit linear regression as a least-squares matrix problem and compare it with statsmodels' regression output, including the t-tests on each coefficient. Students test that their vectorized results match the HOS 1 library values, explain why a broadcast produced the shape it did, and write the covariance matrix of a dataset by hand as a single matrix product.

  • HOS 3 — Gradients, Loss Surfaces & Gradient Descent

Students fit the HOS 2 regression a second way, by gradient descent. They compute partial derivatives and the gradient of mean squared error, plot the loss surface as a contour map, and draw the path gradient descent takes across it. They then change the learning rate, feature scaling, and starting point to produce the common failures: divergence, oscillation, and stalling. Students test whether gradient descent reaches the same answer as the HOS 2 least-squares solution, explain from the contour plot why unscaled features make the path zigzag, and derive the MSE gradient by hand, checking it against a finite-difference estimate.

  • HOS 4 — Likelihood, Loss Functions & Backpropagation

Students connect probability distributions to the loss functions deep learning uses: a Gaussian assumption gives mean squared error, and a Bernoulli assumption gives binary cross-entropy. They build a small two-layer network in NumPy, write its forward and backward passes with the chain rule, and verify every gradient against PyTorch autograd. They then wrap it in a complete training loop with live plots of loss and accuracy. Students test that their hand-written gradients match autograd within tolerance, explain why a yes/no target calls for cross-entropy rather than squared error, and work one backward step through a sigmoid neuron by hand.

  • AC 1 — Exploring and Testing Data in Python

A city bike-share operator tested three pricing-page designs on separate groups of new riders and recorded whether each signed up and how many minutes they rode in the first month. Students choose and run the right test for each question (sign-up rate and minutes ridden) and must pass the provided checks. The open decision is whether to roll out the winning design when the difference is statistically significant but small: about $0.40 more revenue per rider, against a fixed $25,000 redesign cost. Students also identify which of three draft conclusions, written by a teammate, claims more than the p-value supports.

  • AC 2 — Statistics as Linear Algebra

Students receive a regional home-sales dataset with twelve features, several of which nearly duplicate one another. They compute the full correlation matrix as one matrix product of the standardized data, fit a least-squares price model with NumPy, and must pass the provided tests. The open decision is which features to keep before the model goes to a pricing team: at most eight, justified by the correlations and by how much each coefficient moves across bootstrap resamples. Students also explain, in vector terms, why two nearly parallel feature columns make coefficients unstable.

  • AC 3 — Gradients, Loss Surfaces & Gradient Descent

A meal-kit startup's demand model trains for hours and never settles. Students receive the model code and the loss curves from four recorded training runs, and diagnose each run from its curve and a loss-surface plot. They then fix the code so it converges and passes the provided tests. The open decision is the learning rate, scaling, and stopping rule to use under a fixed budget of 2,000 gradient steps, defending the trade-off between final loss and steps spent. Students also explain which single plot told them the most about each failed run.

  • AC 4 — Likelihood, Loss Functions & Backpropagation

A regional transit agency wants three predictions: whether a bus will run late, how many minutes late, and how many riders will board at each stop. Students choose a probability distribution and matching loss for each target, implement the three losses, and train one model per target with provided tests. The open decision concerns the delay-minutes data, which has a long tail of extreme delays from major incidents: keep squared error, switch to absolute error (a Laplace assumption), or handle incidents separately, given the agency's statement that underestimating a long delay costs more than overestimating a short one. Students also explain what each loss assumes about the errors it is penalizing.

Project Description

Teams of three students (four with instructor approval) design, build, and present one end-to-end optimization study on a public dataset that answers a realistic organizational question (O5). The system combines all four HOS:

  • exploratory analysis and statistical inference on the dataset (HOS 1)

  • a tensor and linear-algebra formulation of the model (HOS 2)

  • a gradient-descent training loop with loss-surface diagnostics (HOS 3)

  • a loss function justified by a probability distribution, with gradients verified against autograd (HOS 4)

It also applies the judgment practiced in the Application Challenges, such as when a statistically significant result is not worth acting on and which assumptions a chosen loss makes about the data.

Each team consists of three students. If necessary, a team can be made up of four students with the instructor’s approval. Each team’s role and responsibilities must be clearly described in your team’s final report.

Report

The student will provide a report formatted based on a template provided by the instructor. Students are required to improve their writing iteratively and incrementally every week. The revision will always happen during a quarter. Students will add new required sections to the existing paper every week.

The final report is the culmination of applied research and activities conducted throughout the quarter. The final report provides a detailed problem, and its solution is likely to be encountered by a company or organization described in a case study supplied by the student.

The paper is to be between 5 and 6 pages. The required template for class submissions comes from an international organization, ISCAP (Information Systems & Computing Academic Professionals). The instructor may recommend teams submit their paper to conferences. Submissions are optional and will not impact the course grade. Additional revisions may be required after the course.

The file name consists of the project phase, report type, team number, and the list of your team members. Each report must be maintained in OneDrive to trace team collaboration. Each report must include the team’s GitHub repository named after keywords. Also, in the final report, the YouTube link for the demo must be included. Three report submissions are required according to the following schedule:

  • Proposal (1 page; 10 points)

    • Duration: 3 weeks (Week 1 – Week 3)

    • Purpose: Focus on the organizational question, the dataset and its license, the target variable, key related work, the proposed modeling approach, and ISCAP template compliance.

    • Report Name in OneDrive: “AI251 TP T0X Proposal Author1 Author2 Author3.docx”

    • GitHub Repository: “AI251 TP T0X Your_Study_Name,” which shows the dataset loaded and explored

  • Progress Report (3-4 pages; 30 points)

    • Duration: 5 weeks (Week 4 – Week 8)

    • Purpose: Focus on extended related work, the statistical findings from exploration and inference, the mathematical formulation of the model, early training results, and revision of the proposal based on instructor feedback.

    • Report name in OneDrive: “AI251 TP T0X Progress Report Author1 Author2 Author3.docx”

    • GitHub Repository: “AI251 TP T0X Your_Study_Name,” which shows the working model and training loop

  • Final Report (5-6 pages; 50 points)

    • Duration: 2 weeks (Week 9 – Week 10)

    • Purpose: Focus on findings, the justification of the loss function, convergence diagnostics, conclusions, limitations, future work, complete APA bibliography, and overall publication readiness.

    • Report Name in OneDrive: “AI251 TP T0X Final Report Author1 Author2 Author3.docx”

    • GitHub Repository: “AI251 TP T0X Your_Study_Name,” which shows your team’s final, verified study

    • YouTube Name: “AI251 TP T0X Demo Video Author1 Author2 Author3.”

As in any scholarly writing, students should not merely copy information from another author. Students should use evidence to support the contentions they have drawn from their findings and critically analyze related literature. In essence, each paper needs to be an analytical paper, not a summary of readings.

Students are expected to use the assigned readings, videos, and other materials throughout the quarter. Students will need to utilize additional sources that were not assigned by the professor. While stylized after an industry report, nonetheless, students are expected to employ APA formatting of citations, footnotes, and bibliography. Students must cite the sources of all ideas, facts, and information used that are not their own, even if they have put the information into their own words. Failure to do so is plagiarism, although the oversight is unintentional. To avoid plagiarism, check https://library.cityu.edu/howto/apa-writing/avoid-plagiarism/.

The Muddiest Point (MP) - Grading Criteria

Before starting each module, students are required to submit the Muddiest Point (MP) activity. The purpose of this activity is to stimulate student engagement. The instructor uses the MP to assess how students understood each module’s HOS and its required readings. The instructor also uses the MP to customize the lecture scope to implement Just-in-Time Teaching (JiTT).

The MP consists of four short fields:

  1. What you were doing right before you got confused (the specific concept, video timestamp, or line of the guide).

  2. The exact place you got stuck — not "I don't get gradients," but "I don't understand why we step in the negative gradient direction when the gradient points uphill."

  3. What you already tried — re-reading, a specific search, asking a classmate — before submitting.

  4. Optional: your best guess at the answer, even if you think it's wrong.

Concept Debate (CD) – Grading Criteria

Students engage in a structured discussion of their reasoning with classmates. Each HOS comes with a Concept Debate question, already provided in the course, rooted in that HOS’s key concepts. Each question has two defensible sides, and students consider both before reaching a position of their own.

Before the first debate, every student joins one of two debate groups. The instructor can assign the groups, or students can choose their own, as long as the two groups stay close to even in size. The groups take turns arguing Side A and Side B from one debate to the next.

In the first week of each HOS, students complete a three-stage response sequence:

  1. Initial position (assigned side): Present a clear argument for the side your debate group is assigned, using a specific claim and supporting evidence rather than a general summary.

  2. Argue the opposite side: Before responding to a classmate, post the strongest argument for the opposing side, the position you did not initially hold. Because everyone engages with both perspectives, “I agree with you” is not a valid response.

  3. Synthesis: Set aside advocacy and state a genuine synthesis or consensus position. Reference at least one specific point from a classmate’s post, and avoid generic responses like “great points, I agree.”

Knowledge Check (KC)

Quizzes assess your understanding of key concepts learned through HOSs. Emphasize grasping underlying principles over rote memorization when preparing for the quizzes. Each question has a 90-second time limit, simulating the pace of industry certification exams, so questions test interpretation (reading a plot, choosing a test, predicting a tensor's shape) rather than long calculations.

Students are required to adhere to the honor code, which strictly prohibits the use of AI assistants. You may retake each exam as many times as needed, and a passing score is set at 80%. After every attempt, you will receive feedback on any questions answered incorrectly to help guide your learning.

Design notes — what we took from CS 251 (planning only)

This section is for course designers and is not part of the student syllabus. Remove it before the Brightspace copy.

Verdict: don't follow CS 251; reuse its statistics sequence inside HOS 1

The CS 251 syllabus (May 2024) and schedule (April 2024) were reviewed. CS 251 spends all ten weekly modules on classical statistics in R, following Statistical Analysis with R for Dummies chapter by chapter. The AI 251 description covers only part of that ground (t-tests, ANOVA, regression) and adds three topics CS 251 never touched: linear algebra for tensors, multivariable calculus, and backpropagation. Following CS 251's structure would spend roughly 80% of the course on 30% of the description, so its statistics sequence is compressed into HOS 1 and the regression unit moves into HOS 2, where it becomes the bridge to linear algebra.
