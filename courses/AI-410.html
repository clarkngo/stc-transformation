AI 410: AI Engineering — 10-Week Course Schedule

5 Credits Prerequisites: CS 352, DS 479 10 Weeks Capstone: Agent-Driven Mobile App

Course Description: AI Engineering applies rigorous software engineering principles to the development and deployment of autonomous, learning-based systems. This course emphasizes leveraging Large Language Models (LLMs) within purpose-built software solutions to address real-world business challenges. Students will explore system architecture for agent development and integration, context engineering through Retrieval-Augmented Generation (RAG) and vector databases, and best practices for deploying and monitoring AI models in production environments. The curriculum also covers probabilistic logic for handling nondeterministic outputs. Learners gain hands-on experience building a full-stack AI solution, focusing on asynchronous data processing, push-based AI notifications, and seamless integration of vector stores for dynamic RAG applications. Mastery of these concepts will equip students to design and implement robust AI-powered applications using full-stack AI.

Outcomes

As a result of this course, students will know or be able to do the following:

  1. O1 — Define and explain the essential components of full-stack AI systems, such as LLM architecture, agentic loops, and the differences between prompt engineering and context engineering.
  2. O2 — Design and implement a Retrieval-Augmented Generation (RAG) pipeline using vector databases to deliver context to autonomous agents.
  3. O3 — Analyze and break down the multi-layered architecture of agent-driven applications to identify and address potential bottlenecks in asynchronous data processing and nondeterministic reasoning.
  4. O4 — Evaluate and critique the performance and reliability of production AI models using appropriate observability tools and metrics for assessing probabilistic outputs.
  5. O5 — Develop a fully functional, agent-driven mobile application that seamlessly integrates real-time notifications and persistent vector storage into a comprehensive full-stack solution.

Who This Schedule Is Designed For

STC's AI Engineering cohort skews toward students who are new to production software concepts — many arrive via CS 352 and DS 479 with programming fundamentals but limited exposure to backend infrastructure like queues, vector databases, or observability tooling. The schedule below is built around four scaffolding principles, drawn from research into how other hands-on AI programs teach non-technical and beginner audiences (see Research & Design Rationale below).

1. One running app, not ten disposable ones

Every week extends the same app rather than starting a new project from scratch. Students always know what they're building toward, and each week's work is visibly load-bearing for the capstone.

2. A starter scaffold every week

Students never face a blank repo. Each week ships with working boilerplate for everything except that week's new concept, so effort goes into the one skill being taught, not re-deriving plumbing.

3. Managed, low-code infrastructure for the hard backend pieces

Vector databases, queues, and observability run on pre-provisioned free/managed tiers (e.g. Supabase pgvector, Upstash Redis, Langfuse, Expo Go) so students engineer at the application layer instead of standing up infrastructure — the same reason no-code AI programs keep infra out of the learner's hands.

4. A mid-course checkpoint before the hardest weeks

Week 5 pauses new material entirely for an architecture review, so students consolidate what they've built before the course's two most infrastructure-heavy weeks (async processing, mobile + push).

Weekly Breakdown

Week 1 — Foundations of Full-Stack AI Systems

Scaffold: a working chat UI + backend stub, already deployed to a free host — nothing to configure before class.

Introduces LLM architecture at the level a full-stack engineer needs (context windows, tokens, API shape) and draws the line between prompt engineering (what you ask) and context engineering (what the model can see).

App milestone: Replace the stub LLM call in the starter repo with your own — the app answers its first real question. This becomes the base every later week builds on.

Outcome 1

Week 2 — Structured Outputs & the Agentic Loop

Scaffold: agent-loop skeleton with one dummy tool already stubbed in, so the plumbing for "model decides, tool executes, result returns to model" is visible before students write their own.

Covers the ReAct-style agentic loop, function/tool calling, and structured JSON outputs — the core pattern behind every agent students will build for the rest of the course.

App milestone: Add a real tool (e.g. a calculator or lookup call) to the loop, so the agent can choose to use it mid-conversation.

Outcome 1

Week 3 — Embeddings & Chunking (Context Engineering I)

Scaffold: a sandbox notebook pre-loaded with a small sample document set and a managed embeddings API key — no self-hosted embedding model to configure.

Builds intuition for embeddings and chunking strategies in isolation, before they're wired into the live app next week — matching how beginner-friendly programs introduce one new idea at a time rather than stacking RAG's full pipeline in a single sitting.

App milestone: Write an ingestion script that chunks and embeds the sample documents, and inspect similarity scores directly — not yet connected to the running app.

Outcome 1

Week 4 — Vector Databases & RAG Pipelines (Context Engineering II)

Scaffold: a managed vector database project (Supabase pgvector or Pinecone free tier) is pre-provisioned per student — they receive a connection string, not an infrastructure setup task.

Connects Week 3's embeddings to a persistent vector store and a retrieval step, completing a first working RAG pipeline.

App milestone: Wire retrieval into the Week 2 agent. The app now answers questions grounded in the documents embedded last week — RAG is live.

Outcome 2

Week 5 — Checkpoint: Architecture & Bottleneck Review

Scaffold: a shared diagramming template and an instructor-led review rubric. No new API or build task this week.

No new material is introduced. Students step back and diagram their app's current architecture — LLM call → agent loop → tool calls → RAG → vector store — and identify, in writing, where nondeterminism or latency could break the system before it gets harder to reason about. This directly targets the analytical half of Outcome 3, which the build-only weeks around it don't exercise on their own, and mirrors the consolidation break other programs use before their most infrastructure-heavy modules.

Deliverable: a short written/diagrammed Architecture & Bottleneck Review, reviewed live with the instructor.

Outcome 3

Week 6 — Probabilistic Logic & Guardrails

Scaffold: a pre-built validation/retry middleware template — students plug in their own output schema rather than writing retry logic from scratch.

Covers handling nondeterministic LLM output: schema validation, retries, and fallback routing — directly informed by the bottlenecks each student flagged in Week 5.

App milestone: Add a guardrail layer to the RAG agent so malformed or hallucinated responses are caught and retried instead of surfacing to the user.

Outcome 3

Week 7 — Asynchronous Data Processing

Scaffold: queue and worker boilerplate pre-wired to a managed, serverless Redis instance (Upstash free tier) — students write job logic, not queue infrastructure.

Introduces event-driven, background processing so long-running work (like document ingestion) stops blocking the app — the layer most students without backend experience haven't touched before.

App milestone: Move document ingestion to a background job and add a job-status endpoint, so uploading new documents no longer freezes the app.

Outcome 3

Week 8 — Mobile Client & Real-Time Push Notifications

Scaffold: a pre-built Expo Go mobile shell already wired to the student's backend API — no Xcode or Android Studio required. Students test on their own phone by scanning a QR code.

Connects the backend to a real mobile client and adds push notifications tied to backend events, using Expo's push service over FCM/APNs.

App milestone: Run the app on your own phone and receive a real push notification the moment a Week 7 background job finishes.

Outcome 5

Week 9 — Observability & Evaluation

Scaffold: a Langfuse (or equivalent) project pre-provisioned per student — instrumentation is a handful of added lines, not a dashboard built from scratch.

Covers tracing, latency/cost tracking, and RAG-specific evaluation metrics (faithfulness, retrieval precision) for judging probabilistic output in production.

App milestone: Instrument the full pipeline — agent, RAG, async job, push — with tracing, and write a short critique of one real failure the dashboard surfaces.

Outcome 4

Week 10 — Capstone Integration, Deployment & Demo

Scaffold: a one-click deploy template (Docker + free-tier host) prepared in advance so deployment mechanics don't compete with final debugging time.

Final integration, hardening, and a live demo of the complete system built week over week.

App milestone: Deploy the finished agent-driven mobile app — RAG, guardrails, async processing, push notifications, and observability, all in one running product — and demo it live for instructor and peer critique.

Outcome 5

Research & Design Rationale

To calibrate pacing for an audience newer to production software concepts, three representative hands-on AI programs were reviewed. None is a direct template — AI 410's outcomes require real full-stack engineering (async processing, a real mobile app, production observability), which rules out going fully no-code — but each contributed a specific scaffolding technique used above.

Non-Technical Audience

MIT No-Code AI and Agentic AI Program

14 weeks, explicitly targets "professionals from technical and non-technical backgrounds" (PMs, business leaders, non-CS founders). Six weeks of core concepts, then a dedicated consolidation/break week, before advancing into RAG (week 9) and agents (weeks 12–13). Three capstone projects, each scoped to one new capability rather than integrating everything at once. Keeps the entire curriculum no-code (KNIME, n8n) — no mobile app — precisely because the audience is non-technical.

  • Borrowed: the mid-course consolidation checkpoint (→ AI 410 Week 5) and gating each capstone project to a single new capability.
Technical Audience

Data Science Dojo — Agentic AI Bootcamp

The closest structural match in length and topic sequence: 10 weeks, vector databases, RAG, agentic design patterns, protocols (MCP/A2A), and a multi-agent capstone in week 10. But prerequisites are "basic Python" plus prior LLM/transformer/embeddings knowledge, and it targets ML engineers, backend engineers, and solutions architects — the pacing assumes a technical audience and moves faster than appropriate here.

  • Borrowed: the overall 10-week length and topic ordering (vector DBs/RAG → agent patterns → evaluation → capstone).
  • Not borrowed: its pacing — most weeks introduce 3–4 new concepts simultaneously, which AI 410 deliberately avoids.
Beginner-First

No Code MBA — Building Apps with AI

Genuinely beginner-first: the only stated prerequisite is "a willingness to learn." Rather than one compounding capstone, it teaches through 11 small, standalone apps (a chatbot, a PDF-chat app using embeddings and Pinecone, an image generator), each built in under two hours, introducing one new API or concept at a time before anything is combined.

  • Borrowed: the "one new concept per week, everything else pre-wired" scaffolding pattern, adapted so each week extends one running app instead of starting a new one.

Research conducted August 2026 to inform this schedule's pacing and scaffolding decisions; not a formal literature review.
