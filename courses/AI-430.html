In plain terms: building a model or an agent is the first 10% of the job. This course is the other 90%: versioning the data, tracking experiments, shipping every change automatically, watching the system in production, and making it safe to leave running. You'll do it for a classic ML model and for an AI agent, and see where the two differ.

Course Description: In-depth lifecycle management for both ML models (MLOps) and autonomous AI agents (AgentOps). Covers DataOps, experiment tracking, CI/CD/CT pipelines, multi-step reasoning traces, long-term memory, agent-to-agent communication, LLM-based evaluation, and safety guardrails.

Course Outcomes

As a result of this course, students will know or be able to do the following:

  1. O1 — Understand the architectural differences between traditional software pipelines, MLOps (model-centric), and AgentOps (action-centric) workflows.
  2. O2 — Apply CI/CD/CT principles to automate deployment of machine learning models and agentic workflows.
  3. O3 — Implement observability and monitoring tools to track model drift, agent reasoning accuracy, and system latency in real-time.
  4. O4 — Analyze Vector Database and RAG pipeline performance within an agentic system to optimize retrieval speed and context relevance.
  5. O5 — Evaluate security and ethical risks of autonomous agents, including prompt injection and unintended actions, within an enterprise framework.
  6. O6 — Create an end-to-end “Agentic Pipeline” demonstrating automated tool-use, memory persistence, and robust error handling.

Week 8 architecture review (folded in): diagram one change's full journey, from a data or prompt edit to a monitored production deploy, for both the model and the agent, and mark where each pipeline can fail silently. It's the direct check on O1, and it sets up the project.

Team/Term Project

Create the end-to-end “Agentic Pipeline” in O6: an agent that uses tools, keeps memory across sessions, and handles errors, operated with everything from HOS 1–4. That means it is versioned, deployed by CI/CD, monitored, evaluated, and red-teamed. Team or individual.

Example project
  • The agent: a policy-question assistant for a CityU office that answers from its documents (RAG) and can open a ticket (tool use), remembering each user's past questions (memory persistence).
  • HOS 1–2: the document set versioned with DVC; every merge runs an evaluation and deploys to Hugging Face Spaces only if quality holds.
  • HOS 3: Langfuse traces with judge scores and latency; a retrieval benchmark comparing two index settings.
  • HOS 4: a red-team report (prompt injection, unintended actions) and the guardrails that fixed what it found.
Minimum bar
  • Runs deployed, not just in the Codespace, and redeploys automatically on merge.
  • Tool use, memory that survives a restart, and error handling (retries, graceful failure) all shown working.
  • A monitoring view with at least drift or reasoning accuracy, plus latency.
  • A security write-up against a named framework, with at least one finding fixed.

Planning works the same way as in AI 410 and AI 420: early in Week 9, a few days of Scrum-lite planning (a short backlog of user stories, roles if it's a team, a free PM tool; GitHub Projects recommended, Trello or Notion also work), then straight into building, with standups while you build and the Week 10 demo as the review. You've had the idea since Week 1 and a checkpoint in Week 6, so Week 9 doesn't start cold.

Feasibility Checklist — Before Any Content Is Built

What has to be tried in a real Codespace (2-core first, then 4-core if needed) on free tiers before a unit's guide is written. If a tool fails, swap it for another that meets the same outcome. Never change the outcome.

HOSWhat to test
HOS 1MLflow's UI loads through a Codespaces forwarded port. DVC works with a local or GitHub-hosted remote, no cloud bucket. Setup time from a blank Codespace.
HOS 2A GitHub Actions workflow can deploy to Hugging Face Spaces using only a free HF token stored as a repo secret. How long a CPU Space takes to build and wake from sleep. Whether a scheduled retrain fits free Actions minutes (unlimited on public repos).
HOS 3Qdrant + Chroma + MLflow together on a 2-core Codespace (or is 4-core needed, halving students' free hours?). Ragas and the LLM judge: model calls per evaluation run vs. Gemini free-tier limits. Evidently report generation time.
HOS 4promptfoo (Node) and garak (Python) both install in Codespaces; model calls per red-team scan vs. free-tier limits, and whether a smaller model can act as the attacker. a2a-sdk: two agents talking over forwarded ports.
