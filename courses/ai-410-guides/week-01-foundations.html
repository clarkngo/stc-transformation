Week 1 — Foundations of Full-Stack AI Systems

Est. 3–4 hrs Outcome 1 Starts the app you'll build all term

Goal

Get the starter chat app running end to end, then replace its hardcoded reply with a real call to Gemini. By the end you'll have one working request/response loop — the base every later week extends.

What you'll need

  • Starter code: this week's starter-code folder — copy it into your own project and follow its README
  • Python 3.11+ and a terminal
  • It already contains a /backend FastAPI app with a stubbed /chat endpoint, and a /frontend folder with a single working chat page wired to call it
  • A free Gemini API key (no credit card required) from aistudio.google.com/apikey

Steps

  1. Read the stub before touching it

    Open backend/main.py. Find the /chat handler — right now it just returns a hardcoded string. Note the shape: it receives a JSON body with a message field and returns JSON with a reply field. That shape doesn't change all term; only what happens inside the handler does.

  2. Set your API key as an environment variable

    Never paste it directly into a file you might commit. 
    export GEMINI_API_KEY="your-key-here"

  3. Install dependencies

    cd backend
pip install -r requirements.txt   # fastapi, uvicorn, google-genai

  4. Replace the stub with a real Gemini call

    from google import genai
client = genai.Client()

@app.post("/chat")
def chat(body: ChatRequest):
    interaction = client.interactions.create(
        model="gemini-flash-latest",
        input=body.message,
    )
    return {"reply": interaction.output_text}

  5. Run it

    ./venv/bin/uvicorn main:app --reload
    Use the venv's own uvicorn binary (not just uvicorn) — if your system already has a global uvicorn or google-genai install, an unactivated shell will silently run those instead of the ones in this project's venv. Open frontend/index.html in your browser and send a message. You should get back a real, coherent answer — not the placeholder text.

  6. Understand what just happened

    Look at the raw interaction object (print it before reading .output_text) — it's built from a list of steps, which is the same structure you'll use for tool calls starting next week. Note the usage/token fields on the response — this is the token budget you'll be thinking about all term, and the context window is simply the ceiling on how much of that budget one request can use.

You'll know it worked when…

  • You type a question in the chat UI and get a real, on-topic Gemini-generated answer back.
  • You can point to the exact line of code that makes the LLM call and explain what's in the request and what's in the response.

Common snags

  • "invalid API key" — check the environment variable name matches exactly, and that you restarted the terminal/server after setting it.
  • CORS errors in the browser console — the starter repo's CORS middleware already handles this; don't remove or "simplify" it.
  • Reply looks empty or broken — confirm you're reading interaction.output_text and not the whole interaction object.
