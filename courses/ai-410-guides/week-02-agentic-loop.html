Week 2 — Structured Outputs & the Agentic Loop

Est. 3–4 hrs Outcome 1 Builds on Week 1

Goal

Give your Week 1 chat app a real tool it can decide to use — the core "agentic loop" pattern (model decides → tool runs → result goes back to the model) that every later week reuses.

What you'll need

  • Starter code: this week's starter-code folder — an agent-loop skeleton with one dummy tool already stubbed in and wired
  • Your working Week 1 app (or just use this week's starter code, which already includes it)

Steps

  1. Trace the loop before adding anything

    Follow the dummy tool through the skeleton: (1) the tool's schema is passed to Claude alongside the message, (2) if Claude's reply has stop_reason == "tool_use", the loop runs the matching Python function locally, (3) the result is sent back to Claude as a tool_result message, (4) Claude replies again — this time with a normal text answer.

  2. Define your own tool's schema

    Pick something simple and deterministic — a calculator or a lookup function. Every tool needs a name, a description (this is what the model reads to decide when to use it), and an input schema: 
    tools = [{
    "name": "calculate",
    "description": "Evaluate a basic arithmetic expression.",
    "input_schema": {
        "type": "object",
        "properties": {"expression": {"type": "string"}},
        "required": ["expression"],
    },
}]

  3. Write the function the tool actually runs

    Keep it small and safe (don't use a raw eval on untrusted input in anything beyond this exercise — use a proper expression parser).

  4. Register it and complete the loop

    Pass tools=tools in your messages.create() call. When the response contains a tool_use block, run your function, then send a follow-up message with a tool_result block containing the tool_use_id and your function's output.

  5. Test the "decides" part, not just the "uses" part

    Ask something that needs the tool ("what's 342 × 87?") and confirm it's actually called — print the tool_use block so you can see it. Then ask something unrelated ("what's the capital of France?") and confirm the agent answers directly, without calling the tool.

You'll know it worked when…

  • The agent calls your tool for questions that need it, and skips it for questions that don't.
  • You can show the raw tool_use block in the API response as proof the model — not your code — made the decision.

Common snags

  • Mismatched tool_use_id — the follow-up tool_result must reference the exact ID from the tool_use block, or Claude will error.
  • Infinite loop — always add a max-turns guard; don't assume the model will stop calling tools on its own.
  • Vague tool description — if the model calls the tool when it shouldn't (or doesn't when it should), tighten the description first before changing anything else.
