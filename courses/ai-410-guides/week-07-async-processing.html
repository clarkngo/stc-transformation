Week 7 — Asynchronous Data Processing

Est. 4–5 hrs Outcome 3 New mental model: a second process

Goal

Move document ingestion off the request/response path entirely, into a background job, so uploading a new document never blocks the chat feature. This is the week most students without backend experience feel the biggest jump — take it step by step.

What you'll need

  • Starter code: this week's starter-code folder — includes working queue/worker boilerplate
  • A managed Redis instance (Upstash free tier) connection URL

Steps

  1. Understand the two pieces before writing code

    The boilerplate has two files: an enqueue() helper that adds a job to the Redis queue, and a worker.py — a separate long-running process that pulls jobs off the queue and runs them, one at a time, outside your API's request/response cycle.

  2. Turn ingestion into a job function

    Take your existing chunk → embed → insert logic and move it into a plain function the worker can call — it no longer needs to return an HTTP response, just do the work. 
    def ingest_job(doc_path):
    chunks = chunk_document(doc_path)
    vectors = embed(chunks)
    insert_into_db(chunks, vectors)

  3. Change the upload endpoint

    Instead of running ingestion inline, enqueue it and return immediately: 
    @app.post("/documents")
def upload(doc: UploadedDoc):
    job = queue.enqueue(ingest_job, doc.path)
    return {"job_id": job.id}

  4. Add a status endpoint

    @app.get("/jobs/{job_id}")
def job_status(job_id: str):
    job = queue.fetch_job(job_id)
    return {"status": job.get_status()}   # queued / started / finished / failed

  5. Run the worker as its own process

    Keep uvicorn running in one terminal for your API, and in a second terminal start the worker: 
    python worker.py
    This is the core new idea this week: the worker is not started by your API — it's a separate program you have to remember to run.

  6. Prove it end to end

    Upload a document, confirm you get a job ID back instantly (not after ingestion finishes), then poll /jobs/{id} until it flips to "finished." While it's still running, send a normal chat message and confirm the app stays responsive.

You'll know it worked when…

  • Uploading a document returns a job ID instantly, not after ingestion completes.
  • The chat feature keeps working normally while a document is still being processed in the background.

Common snags

  • Jobs stuck "queued" forever — almost always means you forgot to start worker.py in its own terminal.
  • Worker crashes on missing API keys — it's a separate process with its own environment; env vars set for your API terminal don't automatically apply there.
