Week 10 — Capstone Integration, Deployment & Demo

Est. 5–6 hrs Outcome 5 Everything, together, live

Goal

Deploy the app you've built week over week — RAG, guardrails, async processing, push notifications, and observability — and demo the whole pipeline live, working, on infrastructure that isn't your own laptop.

What you'll need

  • Starter code: this week's starter-code folder — includes a Dockerfile and a Render deploy config for both the API and worker
  • Everything from Weeks 1–9 working locally

Steps

  1. Full local run-through first

    Before touching deployment, walk the entire pipeline end to end on your laptop: web/mobile client → chat → RAG → guardrails → async ingestion → push notification → traced in Langfuse. Fix anything that regressed since Week 9 now, while it's still easy to debug locally.

  2. Review the Dockerfile

    It packages your FastAPI backend. Confirm requirements.txt is current — a dependency you installed in Week 7 or 9 but never added to the file is the most common deploy-time surprise.

  3. Set every environment variable on the host

    Claude API key, Supabase connection string, Upstash Redis URL, Langfuse keys, Expo credentials — set each one in the host's dashboard. Never commit them to the repo, even at this final stage.

  4. Deploy two services, not one

    Same lesson as Week 7: your API and your worker are separate processes. Deploy them as two services from the template, both pointed at the same managed Redis and database.

  5. Point the mobile app at the deployed backend

    Swap the API URL in your Expo project from your laptop's local address to the deployed one, and re-confirm push notifications still work against the live server.

  6. Re-run your Week 5 bottleneck list

    Against the deployed version this time. Did anything on that list only show up now that it's running somewhere other than your own machine (e.g. cold-start latency, a missing env var, a timeout that was fine locally)?

  7. Prepare a 5-minute live demo

    Upload a document and show it processing asynchronously (job status endpoint), ask a RAG-grounded question, trigger a push notification, and pull up the corresponding Langfuse trace — the whole pipeline, live, in front of the class.

  8. Present for critique

    Be ready to explain any part of the architecture — this is also where your Week 5 review and Week 9 critique get tested in front of an audience.

You'll know it worked when…

  • A stranger could install Expo Go, scan your QR code (or open your deployed app), use it for real, and receive a real push notification — with zero setup on your laptop involved.
  • You can answer "why did that happen?" for any step in the live demo, backed by a trace, not a guess.

Common snags

  • Works locally, fails deployed — almost always a missing or mistyped environment variable on the host; check the host's logs first.
  • Free-tier hosts spin down when idle — the first request after idle time can be noticeably slow. Mention this honestly during your demo rather than being caught off guard by it live.
