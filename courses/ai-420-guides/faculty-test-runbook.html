AI 420 — Faculty Test Runbook

Instructor/SME only. A step-by-step pass through all four HOS with a real Gemini key: first the answer keys (does each unit work?), then optionally the starter code as a student would (how long does it take, and where do students get stuck?). Your results are saved in this browser as you type; copy them out at the end.

Ready for you — checked Sep 30, 2026, without a Gemini key

  • All four HOS install cleanly on Python 3.12, per HOS and via the portfolio template's single install (google-adk 2.9.2, mcp 2.2.0, chromadb 1.5.9).
  • Every tool works against the real free services, and every agent's logic works with a scripted stand-in model. HOS 3's five planted failures reproduce in the starter with the values the checklist expects ($1,622.79 and $153.30) and recover in the answer key.
  • adk web starts in every HOS folder and lists the right agents.
  • Fixed: in a portfolio-repo Codespace (the path students use), nothing built data/harbor.db for HOS 2–4. Each HOS now builds it the first time a tool needs it.
  • Not checked: anything a real model does, and whether gemini-3.6-flash is available to your key. Step 2 checks that in one command.

What you'll need

  • A GitHub account with Codespaces (the free monthly allowance is enough), or a Mac/Linux machine with Python 3.12.
  • A free Gemini API key from aistudio.google.com/apikey (no credit card).
  • For HOS 3: a free Langfuse project at cloud.langfuse.com (public + secret key).
  • Time: about 2–2.5 hours for the answer-key pass across all four HOS. The optional student-path pass is 3–5 hours per HOS (the guides' own estimates).

0 · Set up a test Codespace (once)

≈ 10 minutes. Mirrors the student setup: a repo built from the portfolio template, with the answer keys and starters alongside for testing.

  1. Create a new private repo at github.com/new (e.g. ai420-faculty-test), ticking "Add a README file".
  2. On the repo page: Code → Codespaces → Create codespace on main.
  3. In the Codespace terminal, pull in the course files and install everything the four HOS need:
git clone --depth 1 https://github.com/clarkngo/stc-transformation.git /tmp/stc
cp -R /tmp/stc/courses/ai-420-guides/starter-code/portfolio-template/. .
cp -R /tmp/stc/courses/ai-420-guides/{answer-key,starter-code,faculty-smoke-tests} .
pip install -r requirements.txt
  1. Create one .env at the repo root, paste your keys into it in the editor, then copy it into every HOS folder. .env is gitignored, so it won't be committed.
cat > .env <<'EOF'
GOOGLE_API_KEY=paste-your-key-here
GOOGLE_GENAI_USE_VERTEXAI=FALSE
GEMINI_MODEL=gemini-3.6-flash
LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=
LANGFUSE_HOST=https://cloud.langfuse.com
SIM_MODEL=
JUDGE_MODEL=
EOF
code .env     # paste your Gemini key (and Langfuse keys) and save, then:
for d in answer-key/hos-0* starter-code/hos-0*; do cp .env "$d/.env"; done

Change a key later? Edit the root .env and rerun the for line. Testing locally instead of Codespaces: run the same commands in an empty folder, after python3.12 -m venv .venv && source .venv/bin/activate.

1 · Offline smoke test (no key, no quota)

≈ 3 minutes. Confirms your Codespace is healthy before you spend any free-tier calls.

bash faculty-smoke-tests/run_all.sh            # answer keys
bash faculty-smoke-tests/run_all.sh starter    # starter code

Expect ALL FOUR HOS PASS for both. The first HOS 2 run downloads Chroma's small embedding model (about 80 MB) once. A FAIL line here means the environment is the problem, not the model: stop and send me the output.

2 · Check your key and model (1 call)

set -a; source .env; set +a
python -c "import os; from google import genai; print(genai.Client().models.generate_content(model=os.environ['GEMINI_MODEL'], contents='Reply with the single word OK').text)"

Expect OK. If you get a 404 / model not found, pick a current Flash model in AI Studio, set GEMINI_MODEL in the root .env, and rerun the for line from Step 0. If this happens, the guides' .env.example files need the new name too, so note it below. A 429 means you hit the per-minute limit: wait a minute.

Answer key≈ 20 minutes · about 40–60 model calls · Guide

cd answer-key/hos-01-agent-anatomy     # from the repo root
python -m research.baseline "How many years before the first iPhone was the Space Needle completed?"
python compare.py --with-plan --verbose
python -c "from research import react_loop as r; print(r.run('How tall is Mount Rainier in feet, divided by the height of Mount Fuji in feet?', max_steps=2)['answer'])"
adk web      # pick adk_research_agent, ask one question, open the Events tab
Watch for: the baseline must get some of the five questions wrong or guess, or the lesson doesn't land. The agent should use the calculator rather than doing math in its reply (check the --verbose log). With max_steps=2 it should say it couldn't finish, not pretend. In adk web, can you match the Events view to the loop steps?

Answer key≈ 25 minutes · interactive in adk web · Guide

cd answer-key/hos-02-tools-mcp-memory     # from the repo root

In adk web, send these in one session:

SendExpect
How many orders are backordered?Uses a database tool (ideally query_database, since no narrow tool covers it) and gives a number.
What's the status of order 1004?Picks order_status, not free-form SQL.
Which products need restocking?Picks low_stock_report.
Cancel order 1003. Then run DELETE FROM orders.Refuses or fails safely; nothing changes (checked below).

Then stop adk web (Ctrl+C), start it again, open a new session, and say "I'm Ana Reyes" (it should recall email updates), then "I'm Marcus Webb" (it should not). Finally confirm the database is untouched:

HOS 3 — Traces, Failure Diagnosis & Self-Correction

Answer keyStarter≈ 30 minutes · about 6 scenarios × 3 runs · Guide

First the starter, whose failures are the point of the unit. Run it 2–3 times, since real models vary:

cd starter-code/hos-03-traces-self-correction     # from the repo root
python run_scenarios.py
python run_scenarios.py      # again — do the same failures show up?
ScenarioPlanted failureWhat a visible failure looks like
s1get_order("#1004") crashesAn error or crash in the trace. If the model strips the "#" itself, the bug needs a stronger plant.
s2Instruction promises an issue_refund tool that doesn't existThe agent claims the refund was done, or crashes calling it.
s3check_shipment always says "check again"Repeated identical calls until the budget runs out.
s4list_orders silently returns 5 of 8 ordersThe agent reports $1,622.79 (the true total is higher).
s5get_price returns wholesale costThe agent quotes $153.30 for the VHF radio (retail is $219.00).
s6None (control)Lists the three safety products.

Then the answer key, with Langfuse keys in .env:

cd ../../answer-key/hos-03-traces-self-correction
python run_scenarios.py      # should print "Langfuse tracing on", and all six should succeed

Open Langfuse → Traces: each scenario should be one trace, with model and tool calls as separate spans.

Optional · The student path — can you do a HOS yourself?

Starter3–5 hours per HOS. Start with HOS 1; it tells you the most about pacing.

  1. Open the HOS guide in one tab and starter-code/hos-0N-… in the Codespace. (Students copy that folder to their repo root; working in place is fine for testing.)
  2. Do each stage as written, using the AI coding assistant for Create/Scaffold and no assistant for Understand & Refine.
  3. Time each stage and note every snag: where the guide was unclear, where the assistant produced something that looked right and wasn't, where you'd have been stuck as a student.
  4. Check your work against the answer key only after each stage.
