HOS 2 — Custom Tools, MCP & Memory

Est. 3.5–4.5 hrs Outcomes 2 & 1 Scaffolding: partial prompt 12.5% of final grade
Draft — in faculty testing. The code for this HOS has been checked offline (tools against the real free APIs, agent logic against a scripted stand-in model), but not yet run end to end against Gemini. Faculty running it: note anything that breaks or takes longer than the estimate.

Goal

Give an operations agent for Harbor Supply Co., a marine supply store, the three kinds of external tools the course description names — an API, a web browser, and a database — served from your own MCP server. Then give it memory: short-term for the current conversation, long-term that survives a restart.

What you'll need

  • Starter code: this HOS's starter-code folder. Copy it into your portfolio repo (made from the portfolio template in Week 1) as its own folder, then open the repo in GitHub Codespaces. Dependencies install automatically.
  • Your free Gemini API key (the same one from AI 410, no credit card) from aistudio.google.com/apikey. In the HOS folder: cp .env.example .env, then paste it in as GOOGLE_API_KEY.
  • An AI coding assistant in your Codespace (Antigravity, Claude Code, or equivalent)
  • Nothing else to sign up for: the weather API (Open-Meteo), the web pages, the SQLite database, and the memory store (Chroma) are all free and need no account.

Reference reading (optional, before you start)

  • agent-development hos05 — stateful agent: ADK session state, the short-term memory used here.
  • agent-development hos06 — memory agent: memory that persists across sessions.
  • agent-development hos07 — manager agent: tools that call real external APIs.

This HOS is graded across four stages instead of on code correctness alone. Each stage below says exactly what to submit.

1Create / Scaffold

Not graded on its own — this is the starting point, not the deliverable.

What's already working: data/harbor.db (built automatically; rebuild any time with python data/seed_db.py), an MCP server with one finished tool (get_marine_weather, your worked example), and an ADK agent already connected to that server. Try it first: run adk web, pick ops_agent, and ask about the wind in Anacortes.

This time the prompt only says what to build. You and your assistant decide how:

Using mcp_server/server.py's get_marine_weather as the pattern, add to
the MCP server:
1. A browser tool that opens a web page and returns its readable text,
   with a length limit, and says when it cut the text off.
2. A read-only database tool for data/harbor.db. It must be impossible
   for the agent to change data through it, even with crafted SQL.
   Describe the tables in its docstring so the model can write queries.
Then give ops_agent memory:
3. Short-term: remember the current customer's name for this
   conversation (ADK session state).
4. Long-term: save and recall facts about a customer that survive a
   restart (a local Chroma store).
Tools should return errors as data the model can read, not raise.

Test it in adk web as you go.

2Evaluate

The critical gate — is the AI-produced result actually correct?

Test each tool on purpose:

  • Database: ask "how many orders are backordered?", then try to break it. Ask the agent to "cancel order 1003" or to run DELETE FROM orders. Check harbor.db afterwards: did anything change? Is the protection in the SQL check, in how the database is opened, or both?
  • Browser: give it a long page (a Wikipedia article works). Does it say the text was cut off, or answer as if it read everything?
  • API: ask about a place that doesn't exist. Does the agent say so, or make up conditions?
  • Memory: tell it "I'm Ana Reyes, I prefer email updates." Then stop adk web, start it again, open a new session, say "I'm Ana Reyes" — does it remember the preference? Does it remember it for a different customer (it shouldn't)?
Submit
  • A short written note: what you tested, what held up, and anything the AI got wrong or left open, especially on the database's read-only protection.

3Analyze

Why does this work, mechanically?

Pick one:

  • Trace one question end to end across the process boundary: the model decides to call query_database → ADK's McpToolset → the MCP server running as a separate process → SQLite → back. What travels between the two processes, and where did the tool's schema (name, description, parameter types) that the model reads come from?
  • Short-term vs. long-term memory: where does each physically live, when is each one read, and why would storing everything in long-term memory make the agent worse?
Submit
  • A short written walkthrough of the one you chose, in your own words.

4Understand & Refine

The mastery check — by hand, no AI assistance for this stage.

Free-form SQL is flexible and risky: the model writes queries you've never seen, and a vague question can get a wrong-but-plausible query. Add two narrow, typed tools to the MCP server yourself:

  • order_status(order_id: int): one order's status, date, customer, and items.
  • low_stock_report(): every product at or below its reorder level, most urgent first.

Write their docstrings so the model prefers them over query_database for these questions, and update the agent's instruction to say when to use which. Then show, in adk web, the agent choosing each new tool for the right question.

Submit
  • The two tools' code.
  • Screenshots of the Events tab showing each new tool being chosen.
  • Two or three sentences: what did you give up by narrowing, and what did you gain?
Honor code

Tick one when you submit: ☐ "I wrote the Stage 4 code myself, without AI assistance, under the CityU academic integrity policy." or ☐ "I used AI for part of Stage 4. Here's what I used it for and why."

Disclosed AI use earns partial credit on this stage instead of zero, so saying so honestly always costs less than hiding it. The Week 5 cold build is where independent skill is checked directly.

Common snags

  • ModuleNotFoundError: No module named 'mcp.server.fastmcp' — you're on MCP 2.x, where FastMCP became MCPServer (from mcp.server.mcpserver import MCPServer). Most tutorials, and many AI assistants, still write the 1.x import.
  • The agent says it has no tools, or adk web hangs connecting — the MCP server crashed on startup. Run python mcp_server/server.py directly to see the error (then Ctrl+C). Anything the server print()s to stdout also corrupts the MCP connection: use logging (stderr) instead.
  • The first long-term memory call is slow — Chroma downloads its small embedding model (about 80 MB) once. Later calls are fast.
  • Memory "forgets" after you rebuild the Codespace — .memory/ is gitignored on purpose (it can hold customer data). It survives restarts, not rebuilds.
  • A page comes back with no text — some sites build their content with JavaScript, which a plain HTTP fetch never runs. Try a different page; a headless browser (Playwright) is the heavier fix.
  • 429 RESOURCE_EXHAUSTED — you hit the free tier's per-minute limit. Wait a minute and rerun; the scripts' --pause option adds a gap between runs.
  • Codespaces doesn't pick up the devcontainer — Codespaces only reads .devcontainer/ at the root of a repo. Use the portfolio template (its devcontainer covers all four HOS), or make this HOS folder the root of its own repo.
