Lesson overview

O112.5% HOS + MP + CD + AC

In AI 410 you built an app with a model inside it. In AI 420 the model decides what happens next. That difference is the whole course, and this HOS makes it concrete: the same five research questions go to a single Gemini call and to a loop you write yourself, and you compare what comes back — including how often the single call confidently guesses.

Week 1 builds the loop (about 60 lines, no framework) and rebuilds it in Google ADK. Week 2 explains it line by line, adds plan-and-execute by hand, and asks when a business problem needs an agent at all.

Anchoring analogy

A single model call is asking a well-read colleague a question in the hallway: you get an answer from memory, right or wrong, and they walk off. An agent is the same colleague at a desk with a browser and a calculator, allowed to look things up and check their math before answering — and to keep going until they're done. The desk, the browser, and the permission to keep going are code you write.

Learning objectives

By the end of the two weeks you will be able to:

  1. Distinguish standard LLM inference from an agentic loop, with evidence from your own runs. O1
  2. Point to where reasoning, planning, tool use, and memory each live in an agent's code. O1
  3. Build a ReAct loop by hand with a step budget, then match it to a framework's event view. O1
  4. Compare ReAct and plan-and-execute on accuracy, steps, tokens, and time. O1
  5. Decide whether a business workflow needs an agent, a single call, or a fixed script. O1

Lecture: from one call to an agent

≈ 75 min3 short partsO1

Three short segments. Pause after each and try the quick check. Anything that stays fuzzy goes in your Muddiest Point.

Part 1 — Inference vs. an agent ≈ 20 min

Inference is one request and one response. The model answers from whatever it learned in training, with no way to check anything. An agent puts the model in a loop: it can ask for an action (a tool call), see the result (an observation), and decide what to do next — until it decides it's done or runs out of steps.

Worked example

"How many years before the first iPhone was the Space Needle completed?" A single call often answers correctly from memory — and sometimes says 47, or confuses the Needle's opening with its design year, with the same confidence. The agent looks up the Space Needle (1962), looks up the iPhone (2007), and calls the calculator: 45. The interesting finding isn't that the agent is right; it's that the single call's right answers and wrong answers look identical.

Part 2 — The four components, in about 60 lines ≈ 25 min

The course description names four components. In a hand-built loop you can point at each one:

contents = [user_question]                      # MEMORY: the growing history
for step in range(max_steps):                   # the loop, with a budget
    response = model.generate(contents, tools)  # REASONING: decide the next move
    if not response.function_calls:
        return response.text                    # done
    contents.append(response)                   # remember what it decided
    for call in response.function_calls:        # TOOL USE: your code runs it
        result = TOOLS[call.name](**call.args)
        contents.append(function_response(result))   # the OBSERVATION
return "I couldn't finish within max_steps."    # honest stop

Planning is the one you can't see here: in ReAct it happens implicitly, one step at a time, inside each reasoning call. Plan-and-execute (your Week 2 build) makes it an explicit, inspectable list.

Quick check

Delete the max_steps limit. What's the worst case — and who pays for it?

Part 3 — Agentic patterns and frameworks ≈ 30 min

PatternHow it worksGood forCost
ReActReason, act, observe — one step at a timeOpen-ended lookups where the next step depends on the last resultMany small model calls
Plan-and-executeWrite the whole plan first, then run each stepTasks whose steps are predictable; plans you want to reviewOne planning call + steps
ReflectionReview your own output, then retry or acceptQuality checks (HOS 3)An extra call per review
RoutingClassify the request, send it to a specialistDifferent kinds of requests (HOS 4)A routing call per request

Google ADK runs the loop for you. That's the point of building it by hand first: when you open adk web's Events tab, every event should map to a line of your loop. If you can't make that mapping, you're using a framework you can't debug.

Teaching note

The lesson depends on the baseline getting some questions wrong. If a new model version answers all five from memory, swap in a question about something recent or obscure before class.

New words this week

Inference
One request to the model, one response back. No actions, no second chances.
Agent
A model in a loop where it can take actions (tool calls), see the results, and decide what to do next until done.
ReAct
Reason + Act: alternating between deciding the next step and taking it.
Plan-and-execute
Write the full plan first, then work through it step by step.
Step budget
The most loop iterations allowed before the agent must stop and say so.

    Concept Debate

    Graded · part of 5% CD categoryDiscussion board · 3 stages
    This week's question

    For a multi-step business task, should you build an agent that decides its own steps, or a fixed workflow that calls the model only where needed?

    You'll argue the side your debate team is assigned, then argue the other one, then drop advocacy and synthesize.

    Your side this HOS

    Sides rotate each HOS. In HOS 1, Debate Team 1 argues Side A and Debate Team 2 argues Side B. Find your team under Communication → Groups in Brightspace. Not in a team? Before posting Stage 1, count the posts on each side and join the side with fewer; if they're tied, take Side A.

    Side A — Let an agent decide the stepsTeam 1 this HOS

    Give the model tools and a goal; let it choose the path.

    • Real requests vary; a fixed script breaks on the first unexpected case.
    • Adding a capability is adding a tool, not rewriting control flow.
    • The agent can recover from a failed step by trying another route.

    Side B — A fixed workflow with LLM stepsTeam 2 this HOS

    Hard-code the steps; use the model only for the parts that need language.

    • Predictable: the same input takes the same path, so it's testable.
    • Cheaper and faster — no model calls spent deciding what to do.
    • Easier to audit when something goes wrong.
    Stage 1 · by Tue

    Initial position

    Argue your assigned side with one specific claim and one piece of evidence — a run, a trace, a simulator setting. Not a topic summary.
    Stage 2 · by Thu

    Argue the opposite

    Before replying to anyone, post the strongest version of the side you didn't hold.
    Stage 3 · by Sat

    Synthesis

    Drop advocacy. State a real position, citing at least one specific point from a classmate's post.
    Weak synthesis"Agents are more flexible but workflows are more reliable, so it depends."
    Strong synthesis"Kai's compare.py table convinced me: ReAct used 4x the tokens of the baseline on questions a two-step script could answer. My position: start with a fixed workflow, and promote a step to an agent only when the requests it handles genuinely vary — which is Priya's support-email example, not the weekly report."

    Grading: Participation — initial position plus response to at least one peer (50%) · Writing — quality of argument and reasoning (50%).

    Application Challenge — does this workflow need an agent?

    5% of courseDesign & justify — no build

    You'll get three short workflow descriptions from a real business. Decide which need an agent, which are better as a single LLM call, and which are a fixed script — and justify each with the four components. "No agent needed" with a good reason is a strong answer.

    Warm-up: agent, single call, or script?

    For each workflow, pick the simplest thing that would work.

    What to submit
    • For each of the three workflows: agent, single call, or fixed script — and why, using reasoning, planning, tool use, and memory.
    • For any you called an agent: which tools it needs and a sensible step budget.
    • One workflow where you'd change your answer if the requirements shifted, and which requirement.

    Grading: Judgment & reasoning (50%) · Transfer to the new scenario (35%) · Clarity (15%).

    "Promote next month's workshop" becomes research → draft → brand review → schedule. HOS 1 gives the plan-and-execute coordinator; HOS 2 the tools and brand-voice memory; HOS 3 a review step that catches off-voice drafts; HOS 4 the team and the eval suite.
