Module 0 — Universal Tooling

Before HOS 1

Operations work happens in configuration files and containers as much as in Python. These show up in every HOS.

The tooling under every HOS.

Containers and Docker

A container packages a service with everything it needs, so it runs the same anywhere. Several services (a vector database, a tracking server) run side by side with Docker Compose.

Why it matters: A 2-core Codespace has limited memory — the feasibility test checks which combinations fit.

YAML

The indentation-sensitive format used by GitHub Actions workflows and Docker Compose files. A wrong indent is a broken pipeline.

Secrets management

Tokens (a Hugging Face deploy token, a Gemini key) live in .env locally and in repository secrets in CI — never in code, never printed in logs.

Why it matters: Automated pipelines are where keys most often leak.

Forwarded ports

Web UIs running in the Codespace (an experiment tracker, a dashboard) are reached through Codespaces' forwarded ports.

Reproducibility as a habit

Pin versions, record seeds, and write down what produced every result. Operations is mostly about being able to answer "what changed?"

Vocabulary check
Image vs. container
the packaged recipe vs. a running instance of it.
Repository secret
a credential stored by GitHub and injected at run time.
Pinning
fixing exact versions so reruns match.
Quick self-check before you continue
  • Where does a deploy token live in a CI pipeline?
  • Why might two services that each work fail together in a Codespace?
  • What does "pin a version" protect you from?

Module A — Pipelines, DataOps & Experiment Tracking

Before HOS 1Outcome 1

Why before you start: a model's behavior depends on code and data and trained weights; an agent's also on prompts, tools, and the model version. You can't operate what you can't trace back.

The MLOps pipeline's first half.

Software vs. MLOps vs. AgentOps

Software ships code. MLOps ships code, data, and a trained model — any can change results. AgentOps adds prompts, tools, memory, and model versions — and outputs vary run to run.

Why it matters: Outcome O1 asks you to explain these architectural differences.

Data versioning

Giving each dataset a version (proposed: DVC), so "model v7" can point to "data v3" and any result can be reproduced.

Data validation

Checking a batch against a schema — types, ranges, allowed values — before it trains anything (proposed: pandera). A failure should stop the pipeline, not degrade the model quietly.

Why it matters: A renamed column trains a worse model with no error unless something checks.

Experiment tracking

Each run records parameters, metrics, the data version, and the artifact it produced (proposed: MLflow).

Why it matters: It turns "accuracy dropped" into "run 14 used data v4."

Model registry

A catalog of trained models with stages (candidate → staging → production). Deployments pick a named version, which makes rollback one step.

Reproducibility for agents

Agents can't be reproduced exactly; their outputs vary. You track the prompt, tools, and model version, and evaluate distributions of outcomes rather than single runs.

Vocabulary check
DataOps
version control, testing, and automation applied to data.
Artifact
a file a run produced, such as a trained model.
Promotion
moving a model to the next registry stage.
Quick self-check before you continue
  • What three things can change a model's behavior?
  • Why validate before training rather than after?
  • What would you track for an agent instead of training data?

Module B — CI/CD/CT for Models & Agents

Before HOS 2Outcome 2

Why before you start: automation is what makes every change ship the same safe way — but a gate only checks what someone thought to measure.

CI, CD, and CT in one pipeline.

CI / CD / CT

Continuous integration: test every change. Continuous delivery: deploy what passes. Continuous training: retrain when data drifts or on a schedule.

Why it matters: Models go stale even when code doesn't change.

Quality gate

A rule a candidate must pass before replacing production: accuracy at least as good, latency and cost within limits, no worse on a key slice. For an agent, an evaluation run (success, cost, latency).

Why it matters: A gate on accuracy alone ships a slower or pricier candidate.

GitHub Actions workflows

YAML files that run jobs on events: push, merge, schedule (proposed for CI/CD/CT, with deployment to Hugging Face Spaces).

Rollback

Redeploying the previous registered version in one step.

Why it matters: Every deploy plan needs one before it's needed.

Versioned test sets

The data the gate evaluates on must be versioned too, or comparisons between candidates mean nothing.

Human approval

Some teams require a person to approve production deploys; others trust the gate. Agents that act in the world raise the stakes.

Vocabulary check
Workflow
an automated pipeline defined in YAML.
Candidate
a newly trained model or changed agent awaiting the gate.
Drift-triggered retrain
retraining because monitoring saw inputs change.
Quick self-check before you continue
  • What does CT add to CI/CD?
  • What would an accuracy-only gate miss?
  • Why version the gate's test set?

Module C — Observability, Evaluation & RAG Performance

Before HOS 3Outcome 3Outcome 4

Why before you start: after deployment, systems degrade quietly. Know which signal warns about which problem — and how each signal can mislead.

What gets monitored, and how.

Data drift vs. concept drift

Data drift: inputs no longer look like the training data. Concept drift: the right answer for the same input changed. Drift reports compare distributions feature by feature (proposed: Evidently).

Why it matters: Drift often warns before accuracy drops.

Reasoning accuracy with an LLM judge

Each agent trace gets a judge score: did it reach the right answer for the right reasons? (Langfuse.) A judge is a model, so check it against human grading.

Why it matters: A judge's own model version can change its scores without the agent changing.

Latency, per span

Report p50 and p95, and per span, so a slow retriever doesn't hide inside a slow total.

Context relevance

Whether retrieved chunks contain what the answer needs — measured on a fixed benchmark of questions (proposed: Ragas-style metrics).

Why it matters: Fast retrieval of the wrong chunks is still wrong.

The retrieval trade-off

Higher top-k and bigger chunks raise relevance and cost latency and prompt tokens; vector databases differ in speed (proposed: Chroma vs. Qdrant).

Why it matters: Tokens often cost more than the retrieval itself.

Alerts vs. dashboards

Alert only on what's rare, urgent, and actionable; everything else belongs on a dashboard.

Vocabulary check
PSI
Population Stability Index — one common drift score.
Benchmark
a fixed set of questions run against each setting.
Top-k
how many chunks retrieval returns.
Quick self-check before you continue
  • Which signal would warn first about a new customer segment?
  • How would you notice your judge got more lenient?
  • What does raising top-k cost besides latency?

Module D — Security, Guardrails & Agent-to-Agent

Before HOS 4Outcome 5

Why before you start: an agent that can act can be talked into acting. You'll attack your own agent in HOS 4 — know the attacks and the layers that stop them.

Where guardrails sit around an agent.

Prompt injection, direct and indirect

Direct: the user types instructions that override yours. Indirect: instructions hidden in content the agent reads — a document, a web page, an email.

Why it matters: Indirect injection means any retrieved text can carry instructions.

Excessive agency

An agent with more tools or permissions than its task needs. One successful injection then does real damage.

Why it matters: The strongest guardrail removes the capability, not the instruction.

Guardrail layers

Least privilege · mark retrieved text as data · action checks before writes (high-impact actions need a human) · output checks for secrets and other people's data.

Why it matters: Marking alone is unreliable; layers together hold.

Red-teaming

Attacking your own system on purpose before others do (proposed: promptfoo or garak), and reporting findings with fixes and residual risk.

Enterprise frameworks

The OWASP Top 10 for LLM Applications names the risk categories; the NIST AI Risk Management Framework organizes the response (Govern, Map, Measure, Manage).

Why it matters: Outcome O5 asks you to evaluate risks within an enterprise framework.

Agent-to-agent (A2A) communication

When agents send each other tasks, each message is a request: check the caller's identity, what it's permitted to ask for, and treat its content as data (proposed: a2a-sdk).

Vocabulary check
Residual risk
what's still possible after your fixes.
Least privilege
only the access a task needs.
Agent card
how an A2A agent describes what it can do.
Quick self-check before you continue
  • Why can't a better system prompt alone stop prompt injection?
  • Which guardrail layer stops an injected "email this to…" most reliably?
  • What should an A2A receiver check first?
