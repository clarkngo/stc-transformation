Twin Lab: warehouse robot & its digital twin

A delivery robot (AMR) has to reach its charging dock. The solid robot stands in for the real machine: it has hidden manufacturing differences, motor latency and sensor noise. The cyan ghost is your digital twin, built from the spec sheet. Drive the robot with a Python node, then measure the gap between twin and robot and close it.

What this prototype is testing, and things to try

Things to try

  1. See the sim-to-real gap. Press ▶ Run with the starter node in Digital model mode. The node steers by wheel odometry. Watch where the robot ends up compared with the twin and the dock.
  2. Assimilate live data. Switch to Digital shadow and run again. The twin pulls itself toward the robot's indoor-positioning fix (/uwb/pose, 5 Hz, noisy).
  3. Calibrate the twin. In Twin calibration, adjust wheel radii, mass, motor gain and latency until replay error drops. Which parameter matters most?
  4. What-if + safety. Choose the pallet scenario in Digital twin mode. The twin predicts the collision and stops the robot. Then edit the node so it routes around the pallet (use /scan).

Why it's built this way

Each piece maps to something employers name: MuJoCo is listed alongside Isaac Sim in robotics simulation postings, nodes use ROS 2's rclpy API and standard message types, and scenes export as MJCF and OpenUSD. The physics is real (DeepMind's official MuJoCo WebAssembly build), so contact, friction, motor saturation and inertia aren't scripted. The full rationale and roadmap are on the plan page.

Not in this prototype yet

Camera sensor and synthetic-data export (HOS 3), robot arm cell, MCAP logs, a Gymnasium-style environment for RL, and a bridge to a real ROS 2 install over rosbridge.
