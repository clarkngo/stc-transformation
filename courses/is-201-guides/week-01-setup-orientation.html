Week 1 — Setup, Orientation & Your First AI Pairing Session

Est. 2–3 hrs CO1 · CO3 Pilot domains: Maritime & Marketing/E-commerce ☁️ Runs in your browser — no local install

Goal

Get a cloud dev environment running in your browser via GitHub Codespaces — nothing to download or install on your own machine — with Python and an AI coding assistant both ready to go. Then write one tiny script with the AI's help and read it back without the AI's help — that two-part habit (pair, then verify) is the one this whole course is built around, and every later module assumes you already have it.

What you'll need

  • A free GitHub account
  • A modern browser — that's genuinely it. No Python install, no VS Code download, no local setup of any kind.
  • An AI coding assistant you can chat with inside your editor (Claude, GitHub Copilot, or similar — the specific tool is still being finalized for the pilot; any of these works for this week)
  • No prior programming experience assumed — this week has almost no "real" code yet
Why Codespaces, and why now: this isn't a one-off choice for this guide — it's the direction STC has already been validating for exactly this reason ("smoothest student setup," per the Sep 1 tooling meeting notes) and the pattern CityUX's own execution plan commits to for lab content generally. Doing it here first is the pilot test for that decision, not a detour from it.

Steps

  1. Make sure you have a GitHub account

    If you don't already have one, sign up for free — you only need the free tier for everything in this course.

  2. Launch this week's Codespace

    Go to the course repository on GitHub, click the green Code button, switch to the Codespaces tab, and click Create codespace on main.
    What's actually happening: GitHub is starting a full Linux computer somewhere in the cloud, pre-loaded from a small recipe file in the repo (.devcontainer/devcontainer.json) that says "this project needs Python 3.11" — and opening a full copy of VS Code for it, right inside your browser tab. The first launch takes a minute or two while that computer is built; every launch after that is much faster.

  3. Confirm your environment is ready

    Once VS Code loads in the browser, open its integrated terminal (Terminal → New Terminal, or the panel that's likely already open at the bottom) and run: 
    python3 --version
    What you should see: something like Python 3.11.x — already there, because the devcontainer recipe installed it before you even arrived. This is the whole point: nothing to troubleshoot on your own machine, because there is no "your own machine" involved.

  4. Set up your AI coding assistant

    Sign in to your chosen assistant inside this browser-based VS Code (each has its own extension — install it from the Extensions panel on the left sidebar, the same way you'd install any VS Code extension, then sign in with your account).
    You are pairing with it, not handing off to it. Starting today, the habit this course builds is: ask the AI to draft something, then read every line it gives you before you run it. That second half — reading — is graded starting next module. This week it's just a habit to start forming.

  5. Create your scratch file

    In the file explorer on the left, create a new file called week1.py anywhere in the workspace.
    This Codespace is disposable scratch space. You don't need to save, commit, or submit anything from it — it's here so you can practice without worrying about breaking or permanently changing anything. Close it when you're done; a fresh one starts clean next time. (A proper personal starter-repo per student, the way AI 410's guides already do it, is still on the roadmap — this week's Codespace is the simplest version of that idea.)

  6. Pick your domain lens

    Module topics stay the same all term, but the examples you work through change depending on which pilot domain you're in. Pick the one for your section below — the code you're about to write matches it.
    # Prompt you'll give the AI assistant (Maritime lens): # "Write a Python script that stores a vessel's name in a # variable and prints a one-line systems-check message using it."

  7. Ask the AI to write it, then read it before running it

    Type the prompt shown above (for your domain) to your AI assistant, right inside VS Code. It will likely hand you something very close to this: 
    vessel_name = MV Example
print(f"Systems check: {vessel_name} is online.")
    Before you run anything — read it. What does that first line — the one with = in it — do? What does the f"..." string do with the variable name inside the curly braces? If you can't answer both in one sentence each, ask the AI to explain those two lines before you go further — that's a legitimate use of it this week.

  8. Run it — and notice what happens

    Save the file, then in your terminal (inside the same folder): 
    python3 week1.py
    You'll probably get an error — something like SyntaxError: invalid syntax, pointing at the second word on that line. That's not your mistake. Look closely at the line the AI gave you: it's missing quotation marks around the text, so Python can't tell that those two words are meant to be one piece of text — it can't even parse the line, let alone run it.

  9. Debug the AI (ungraded warm-up)

    Fix the line yourself — don't ask the AI to fix it for you this time — so it reads: 
    vessel_name = "MV Example"
print(f"Systems check: {vessel_name} is online.")
    Save, run python3 week1.py again, and confirm you now see your systems-check message printed with no errors — e.g. Systems check: MV Example is online.
    Why this matters more than it looks like it does: you just did — in miniature, ungraded — the exact thing this course grades starting next module: an AI assistant produced something with a flaw in it, and you were the one who caught it, not the AI. Quotation marks around text are one of the most common things AI assistants get right almost every time, but "almost every time" is exactly why reading before running is the habit, not typing speed.

You'll know it worked when…

  • Your AI assistant is installed, signed in, and responds inside VS Code.
  • python3 week1.py runs with no errors and prints your domain's systems-check message.
  • You can explain, in your own words, what each of the two lines does — and what was wrong with the AI's first version.

Common snags

  • Codespace stuck on "Setting up your codespace…" — the first build for a new devcontainer can take a couple of minutes. If it's stuck much longer than that, go back to the repo's Code → Codespaces tab, delete it, and create a fresh one.
  • "You've used all of your included Codespaces usage" — free GitHub accounts include a monthly quota of Codespaces hours, not unlimited use. If you're a student, check whether your account is enrolled in GitHub Education for a larger quota; otherwise it resets at the start of your next billing cycle.
  • AI assistant extension won't sign in — try signing in from a regular browser tab first, then retry inside the Codespace; some accounts need email verification the first time.
  • Still getting a SyntaxError after adding quotes — check that both the opening and closing quote are there, and that they're straight quotes (") not the curly ones a word processor sometimes auto-substitutes; a mismatched or missing quote produces the same kind of error.
  • Nothing prints at all — make sure you saved week1.py before running it, and that your terminal is in the same folder as the file (ls should show week1.py in the listing).
