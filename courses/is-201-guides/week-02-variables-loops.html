Week 2 — Variables, Operators, Loops & If Statements

Est. 2–3 hrs CO1 · CO4 Pilot domains: Maritime & Marketing/E-commerce 🎯 Diff/Debug Sprint — graded starting this week

Goal

Learn the four building blocks — variables, comparison operators, while loops, and if statements — by pairing with an AI to write a small monitoring script. Then run this module's first graded Diff/Debug Sprint: find a logic bug that doesn't crash the program, it just quietly produces the wrong answer.

What you'll need

  • Your Week 1 Codespace (or a fresh one — same setup steps if you need a refresher)
  • Your AI coding assistant, signed in and ready

Steps

  1. Pick your domain lens

    Same two pilot domains as Week 1 — pick the one for your section.
    # Prompt you'll give the AI assistant (Maritime lens): # "Write a Python script with a while loop that checks a list of # engine temperature readings and prints an ALERT if any reading # is above 90C, otherwise prints OK."

  2. Ask the AI to write it, then read it before running it

    It will likely hand you something very close to this: 
    vessel_name = "placeholder"
    Before you run anything: find the comparison operator (>, <, ==) and the number it's comparing against. What value is the threshold actually set to?

  3. Run it in your Codespace terminal

    Save as week2.py and run python3 week2.py.
    Notice: this one doesn't crash. Unlike Week 1's SyntaxError, this program runs perfectly and prints something for every reading — which is exactly what makes it dangerous. A crash tells you something is wrong. Wrong-but-confident output doesn't.

  4. Diff/Debug Sprint — graded (timed, ~3 min)

    Compare the AI's draft above against this one — the one line that changed is the threshold in the if statement: 
    vessel_name = "placeholder"
    Run both versions and compare the output. In your own words (a sentence or two, timed to ~3 minutes as if this were the real Sprint), answer: what changed, and what's the real-world consequence of shipping the buggy version?
    What's actually graded from Module 2 onward (per the design brief's assessment rebalance): not whether you can type the fix, but whether you can name the specific flaw and explain its consequence in the domain's own terms — a wrong alert threshold on a real vessel either misses a genuine overheat or drowns the crew in false alarms until they start ignoring every alert, including the real one.

Five questions covering this week's material.

Common snags

  • The buggy version "looks fine" at a glance — that's the point. Read every ALERT/OK line against the actual reading value, not just skim for crashes.
  • Runner says "Loading Python…" for a while — same as Week 1, it downloads a real Python runtime the first time; it's a few MB, so give it a moment on a slow connection.
  • Lost your Week 1 Codespace — that's fine, spin up a fresh one from Code → Codespaces → Create codespace on main; nothing from Week 1 needed to be saved.
