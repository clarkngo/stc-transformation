Week 3 — Lists & Tuples

Est. 2–3 hrs CO2 · CO4 Pilot domains: Maritime & Marketing/E-commerce 🎯 Diff/Debug Sprint — graded

Goal

Work with lists and tuples — ordered collections you'll use constantly from here on — and sort them with sorted(). Then run this week's Diff/Debug Sprint on a bug that isn't a wrong value this time, but a wrong shape: inconsistent indentation, the one place where whitespace itself is part of Python's syntax.

What you'll need

  • Your Codespace from a previous week (or a fresh one — setup steps here)
  • Your AI coding assistant, signed in and ready

Steps

  1. Pick your domain lens

    # Prompt you'll give the AI assistant (Maritime lens): # "Write a Python script that stores a list of (vessel name, fuel # efficiency) tuples, prints each one, then prints them again # sorted by efficiency, most efficient first."

  2. Ask the AI to write it, then read it before running it

    It will likely hand you something very close to this:

    Before you run anything: look at the indentation of every line inside the for loop. Is it consistent? Python doesn't use { } or end to mark a block — the indentation is the block.

  3. Run it in your Codespace terminal

    Save as week3.py and run python3 week3.py.
    This one crashes again — but with a new error type: IndentationError. Unlike Week 1's SyntaxError (a word missing quotes) or Week 2's silent logic bug (a wrong number), this is Python telling you it can't even tell which lines belong inside the loop.

  4. Diff/Debug Sprint — graded (timed, ~3 min)

    The fix re-indents the print line so it's inside the loop, and adds a second block that sorts the list before printing it again:

    Run both, compare the output, and answer: what did the AI get wrong about the loop's structure, and what does sorted(..., key=lambda v: v[1], reverse=True) actually do?
    Why indentation bugs matter more than they look: a copy-paste from a chat window, a mixed-tabs-and-spaces paste, or an AI reformatting a block can silently shift indentation without changing what the code visually seems to say — this is exactly the kind of flaw that's easy to skim past and only Python's own parser catches.

Common snags

  • "Inconsistent use of tabs and spaces" — a related but different error; it means some lines use tab characters and others use spaces for indentation. Fix by re-typing the indentation with your editor's spaces (VS Code shows whitespace characters via View → Render Whitespace).
  • Can't tell if two lines are indented the same — click at the start of each line and check the column number VS Code shows in the bottom status bar; they should match for lines in the same block.
  • Runner says "Loading Python…" for a while — same as previous weeks, first load downloads a real Python runtime.
