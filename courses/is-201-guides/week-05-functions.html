Week 5 — Functions

Est. 2–3 hrs CO1 · CO3 Pilot domains: Maritime & Marketing/E-commerce 🎭 Roleplay Feedback Loop

Goal

Before you write a single line of a function, practice the Roleplay Feedback Loop: brief your AI assistant to play a skeptical stakeholder and push back on a vague request, until the requirements are sharp enough to actually write a function signature from. Then build the function, and run this week's Diff/Debug Sprint on a bug that produces no error at all — just a missing answer.

What you'll need

  • Your Codespace from a previous week (or a fresh one — setup steps here)
  • Your AI coding assistant, signed in and ready

Steps

  1. Pick your domain lens

    # The vague ask you're starting from (Maritime lens): # "Build something that tells the crew how much fuel is left."

  2. Run the Roleplay Feedback Loop

    Give your AI assistant this exact framing prompt (fill in your domain's vague ask): 
    Act as a skeptical operations manager reviewing a request. I want to
build "something that tells the crew how much fuel is left." Before
you agree this is well-specified, ask me clarifying questions.

    What a real exchange looks like

    You: Act as a skeptical operations manager reviewing a request. I want to build "something that tells the crew how much fuel is left." Before you agree this is well-specified, ask me clarifying questions.

    AI (as stakeholder): A few things before I sign off on this: (1) "How much fuel is left" — as a percentage, remaining liters, or estimated hours of operation? Different crew members will assume different things. (2) Is tank capacity the same for every vessel, or does this need to accept a capacity as an input? (3) Is there a threshold where this becomes an alert rather than a routine readout? (4) Who's actually consuming this output — a bridge display, or another automated system?

  3. Turn the transcript into a function signature

    The Roleplay Loop answers the ambiguity: report a percentage, accept both current fuel and capacity as inputs (since capacity varies by vessel), and return a plain number so the caller decides what to do with it. That converts directly into a signature and docstring:

  5. Run it in your Codespace terminal

    Save as week5.py and run python3 week5.py.
    No crash. No error. Just a wrong-looking answer. This is the quietest bug class yet — Week 1 crashed loudly, Week 3 and 4 crashed with a specific error name, but a missing return just silently hands back None, and Python is perfectly happy to print that as part of your message.

Common snags

  • The AI immediately agrees your request is fine — push back explicitly: "You're being too agreeable — a real skeptical stakeholder would find at least two ambiguities here. Try again."
  • Not sure what counts as a "parameter" vs. a hardcoded value — if a value could reasonably be different the next time the function is called (a different vessel's capacity, a different discount percentage), it belongs as a parameter, not baked into the function body.
  • Runner says "Loading Python…" for a while — same as previous weeks, first load downloads a real Python runtime.
