Week 6 — Files & Exceptions

Est. 2–3 hrs CO4 Pilot domains: Maritime & Marketing/E-commerce 🎯 Diff/Debug Sprint — graded

Goal

Write to files and handle exceptions with try/except. Then run the most consequential Diff/Debug Sprint yet: a bug where the code doesn't crash, doesn't print anything wrong — it just quietly throws away a real error and tells you everything is fine.

What you'll need

  • Your Codespace from a previous week (or a fresh one — setup steps here)
  • Your AI coding assistant, signed in and ready

Steps

  1. Pick your domain lens

    # Prompt you'll give the AI assistant (Maritime lens): # "Write a Python function that logs a sensor reading to a file, # but validates the reading first and raises an error if it's out # of a sane range. Wrap the whole thing in error handling."

  2. Ask the AI to write it, then read it before running it

    It will likely hand you something very close to this: 
    placeholder
    Read the except clause specifically. What does it catch, and what does it do once it catches it? Compare that against what the try block can actually raise.

  3. Run it in your Codespace terminal

    Save as week6.py and run python3 week6.py.
    Read the output slowly. It says "Done logging." Nothing about the invalid reading. No error. No warning. The program is telling you it succeeded.

  4. Diff/Debug Sprint — graded (timed, ~3 min)

    The fix narrows what's caught, from a blanket except Exception: pass to catching the specific error and reporting it: 
    placeholder
    Run both, and answer: what did the buggy version actually do with the invalid reading, and why is "catch everything, do nothing" worse than not handling errors at all?
    Why this is the highest-stakes bug so far: every previous module's bug told you something was wrong — a crash, a wrong number you could compare against reality, a missing value. This one actively hides the problem. A real vessel logging system built this way would drop an out-of-range reading and report success, and nobody would know until something failed downstream with no record of why.

Common snags

  • Confusing except Exception with catching nothing — it does catch things, that's the problem: it catches errors you didn't anticipate right alongside the one you did, and treats them all the same way.
  • Not sure your fix actually narrowed the catch — check that the except line names a specific error type (like ValueError), not the bare word Exception.
  • Runner says "Loading Python…" for a while — same as previous weeks, first load downloads a real Python runtime.
