Week 7 — Classes

Est. 2–3 hrs CO1 · CO6 Pilot domains: Maritime & Marketing/E-commerce 🎯 Diff/Debug Sprint — graded

Goal

Design a class on paper before you or the AI writes a single line of it — what attributes does it hold, what can it do — then have the AI implement your design and verify the result actually matches what you sketched. Then run a Diff/Debug Sprint on the single most common class-design mistake: forgetting self. when storing a value.

What you'll need

  • Your Codespace from a previous week (or a fresh one — setup steps here)
  • Your AI coding assistant, signed in and ready

Steps

  1. Pick your domain lens

    # Design target (Maritime lens): a Vessel class # Attributes: name, max_speed_knots # Method: describe() -> a one-line summary string

  2. Design the class on paper first

    Before any code exists, answer three questions in a sentence each: What does one instance of this class represent? What values does every instance need to remember (its attributes)? What can an instance do (its methods)? Write these down — you'll check the AI's implementation against them in a moment.

    Why this ordering matters

    A class is a design decision before it's ever code — what belongs on the object versus what gets passed in fresh each time. Sketching it first means you have an independent answer to check the AI's output against, instead of reading its code and asking "does this seem reasonable?" with nothing to compare it to.

  3. Ask the AI to implement it, then verify against your design

    It will likely hand you something very close to this:

    Check every attribute in __init__ against your paper design. Does each value that should be remembered actually get stored on self? A value can be assigned to a local variable that looks identical to an attribute and still not be one.

  4. Run it in your Codespace terminal

    Save as week7.py and run python3 week7.py.
    Read the error carefully. It names an attribute that "doesn't exist" — but you can see it being assigned right there in __init__. That contradiction is the clue.

Common snags

  • Confusing a local variable with an attribute — if a name appears without self. in front of it inside a method, it's a plain local variable that vanishes when the method returns; only self.name forms attach to the object itself.
  • Not sure why the crash happened later, not immediately — Python only complains about a missing attribute the moment something actually tries to read it, not when the object is first created.
  • Runner says "Loading Python…" for a while — same as previous weeks, first load downloads a real Python runtime.
